密度口径（可复现）与 F / E 差异

法五口径

  • 可点元素 = #panel 内、非 [hidden] 子树中的 button / a / input / select / textarea / 带 tabindex（且非 -1）的元素。
  • 默认屏预算 = 工具栏可点 + 状态栏可点 ≤ 7（本稿：S1 = 5 + 0 = 5；S6 = 5 + 2 = 7）。
  • 不计入：聊天流内消息（记录，不是控件预算）、演示控制台（在 #panel 之外）、页面侧拾取入口。

相对 E 的变化点（只列 5 条）

#E（渐进式披露）F（聊天流统一承载）
1L0 只有「当前那一张决策卡」独占一个槽位，历史收进 L1「已决策历史」对话历史 = 流本身；当前题就是流里最新一条消息，旧卡原样留在上方
2问答在决策卡槽位里就地完成，未入流ask-user 卡内联在流中，应答/取消后固化不可逆（已答：… + 时间戳）
3授权批准就地发生，事后在审计里查权限申请卡入流，批准/拒绝固化 + 时间戳 + 「查看审计」跳转；授权记录可见
4引用失效住在 #risk-rail（常驻风险位）失效 = 系统事件行 + 失效引用卡（卡内「重新拾取 / 改用描述」）+ 状态栏 chip，三处呼应
5状态栏是「入口按钮」：点开是 L2 入口面板状态栏右移为常驻状态 + 风险 chip；四个视图入口上移到工具栏（一行 5 个可点）

已知取舍

  • 流会随会话变长 —— 靠「自动滚到底 + 可上滚回看 + 系统事件行轻量化」控制感知重量；长会话的折叠/摘要策略留给重构。
  • 工具栏只有 5 个可点位置，因此「宽度切换」「场景切换」在交付 UI 里不存在（它们只在演示控制台）。
  • 风险 chip 的详情是状态栏内联展开，不是浮层 —— 避免与「法一：一次性交互禁止浮层」擦边。
