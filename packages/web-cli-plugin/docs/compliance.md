# 站点自动化条款合规评估（FR-030 / TASK-002；P1 TASK-014 补强不适用清单）

> **文档定位**: 站点条款合规评估（ToS / robots / 自动化约束）→ 可用性结论（可用/受限/禁用）+ 依据；试点站点先行（O-009）。
> **范围**: 首版试点站点 = LGDL Web Workbench（实例站点）+ 本地非 LGDL fixture 站点。真实第三方站点在「启用前」逐一评估后追加。
> **可追溯**: 每条结论含依据与评估时间；变更可审计（NFR-010）。

## 1. 评估口径

| 维度 | 评估内容 | 结论口径 |
|------|---------|---------|
| ToS（服务条款） | 是否禁止自动化访问/操作 | 允许 / 未禁止但受限 / 明确禁止 |
| robots.txt | 是否 Disallow 目标路径 | 允许 / 受限 / 禁止 |
| 账号风控 | 自动化是否触发风控/封禁 | 低 / 中 / 高 |
| 数据外泄面 | 页面数据是否经 LLM 外发 | 用户知情同意后可控 / 高敏感不建议 |

## 2. 试点站点结论

### 2.1 LGDL Web Workbench（实例站点）

| 维度 | 结论 | 依据 |
|------|------|------|
| ToS | **可用** | 本项目自有站点（LGDL 仓库 GH Pages 子路径），作者拥有完全处置权 |
| robots | **可用** | 无禁止自动化条款；站点主动声明 web-cli 协议（`/.well-known/web-cli.json` + `<link rel="web-cli">`），即显式欢迎协议消费端接入 |
| 账号风控 | **低** | 无账号体系；操作对象为本地编辑器文档 |
| 数据外泄面 | **可控** | 文档内容经用户 BYOK LLM 处理；key 隔离于扩展存储，不进页面/日志/审计 |
| **总判定** | **可用** | 站点为协议「实例站点」，非特例硬编码（FR-041/043） |

### 2.2 非 LGDL fixture 站点（本地测试站点）

| 维度 | 结论 | 依据 |
|------|------|------|
| ToS | **可用** | 本地自建 fixture（`test/fixtures/site/`），无第三方条款 |
| robots | **可用** | 本地静态伺服，无 robots 约束 |
| 账号风控 | **低** | 无账号 |
| 数据外泄面 | **无** | 纯本地内存 notes，不外发 |
| **总判定** | **可用** | 用于通用性验证（FR-043/AC-010），非产品交付站点 |

## 3. 站点类型可用性分级（试点）

| 站点类型 | 判定 | 说明 |
|---------|:----:|------|
| 自有站点（主动声明 web-cli） | 可用 | 协议显式接入 |
| 本地/开发站点 | 可用 | 无第三方条款 |
| 第三方站点（未评估） | **受限（默认）** | 启用前须逐站评估；未评估不得启用（默认 untrusted + 未授权拒绝） |
| 明确禁止自动化的站点 | **禁用** | 见 §4 |

## 4. 不适用清单（FR-032）

> 本清单是插件**明确不适用 / 不承诺**的边界；用户可据此判断某站点/操作是否可用。
> 与 §1 评估口径、§3 分级一致（NFR-010 可追溯）。用户可见入口：options 页「合规与能力边界」（指向本文件）。

### 4.1 明确禁止自动化的站点类型（禁用）

| # | 站点类型 | 判定 | 依据 |
|---|---------|:----:|------|
| S-1 | 服务条款明确禁止自动化访问/操作的站点 | 禁用 | ToS 冲突 |
| S-2 | robots.txt `Disallow` 目标路径且未获授权的站点 | 禁用 | 站点意愿 |
| S-3 | 需要绕过验证码 / 风控 / 访问控制才能操作的站点 | 禁用 | 违反站点安全机制 |
| S-4 | 金融交易、支付、医疗、政务等高风险且未获明确授权的站点 | 禁用 | 高风险 + 无授权 |
| S-5 | 明确禁止第三方客户端接入的封闭平台 | 禁用 | 平台条款 |
| S-6 | 要求规避账号体系 / 多账号批量操作的场景 | 禁用 | 风控/条款 |
| S-7 | 未声明 web-cli 协议且无法经用户授权访问的站点 | 不可用（技术） | 协议不匹配/未授权 |

### 4.2 明确禁止 / 不承诺的操作类型（禁用）

| # | 操作类型 | 判定 | 说明 |
|---|---------|:----:|------|
| O-1 | 破解 / 绕过站点安全机制（验证码、风控、权限校验） | 禁用 | 不做、不提供绕过入口 |
| O-2 | 未获用户显式授权的跨 origin 操作 | 禁用 | S1 策略拒绝 |
| O-3 | 抓取 / 导出站点明确禁止的数据 | 禁用 | 条款冲突 |
| O-4 | 代替用户完成需要人工确认的高风险决策 | 禁用 | 需人工介入 |
| O-5 | 自动执行支付 / 下单 / 转账 / 签署等不可逆交易 | 禁用 | 高风险不可逆 |
| O-6 | 批量注册 / 刷量 / 群发 / 爬取全站等滥用行为 | 禁用 | 账号风控 + 条款 |
| O-7 | 隐藏自动化身份以规避检测 | 禁用 | 违反站点风控意愿 |
| O-8 | 高频轮询 / 无节制调用 | 受限 | 经风控护栏限速（FR-029 令牌桶） |
| O-9 | 未评估的第三方站点 | 受限（默认） | 启用前逐站评估；默认 untrusted + 未授权拒绝 |
| O-10 | 读取 / 外发站点明确标注为敏感的数据 | 受限 | 脱敏 + 用户确认；高敏感不建议 |

### 4.3 处置原则

- 命中「禁用」→ **不做**（插件不提供该能力，也不提供绕过路径）；不静默假装成功。
- 命中「受限」→ 经门禁 / 二次确认 / 风控护栏后**有条件可用**；用户可随时暂停 / 中止（FR-029）。
- 结论变更须记录依据与时间（NFR-010）。

## 5. 用户告知与知情同意（FR-031 要点）

授权流程（side panel「授权当前站点」）须含风险提示：
- **账号风控**：自动化操作可能触发站点风控/封禁；
- **条款冲突**：可能与站点服务条款冲突；
- **数据外泄**：页面数据将经用户自备 LLM key 处理，存在外发面；
- **能力边界**：插件仅在用户授权 origin 内、经门禁裁决后操作。

（P0 已在 side panel 授权按钮文案中给出概要提示；完整风险提示文案由 TASK-014 补强。）

## 7. LLM 厂商端点直连结论（FR-034 / EC-009）

> 插件在 **background service worker** 发起 LLM 请求；扩展以自身 origin 访问 `host_permissions` 覆盖的端点，**不受宿主页面 CORS 预检约束**（与页内内置助手的浏览器直连口径不同）。逐厂商结论如下：

| 厂商 | 端点 host | 承载 | 直连结论 | 依据 / 证据 |
|------|-------------------|------|:--:|------|
| DeepSeek | `api.deepseek.com` | OpenAI 兼容 | **可直连** | manifest `host_permissions` 覆盖；SW 扩展源 fetch 无页面 CORS |
| Qwen 通义千问 | `dashscope.aliyuncs.com` | OpenAI 兼容 | **可直连** | 同上 |
| 火山方舟 · 通用 | `ark.cn-beijing.volces.com` | OpenAI 兼容 v3 | **可直连（已实测可达）** | G-KEY：SW 内带 Authorization fetch 返回 **HTTP 401**（非 CORS/网络失败）；`browserDirect:false` 为页内助手时代的保守标记 |
| 火山方舟 · Coding | `ark.cn-beijing.volces.com` | OpenAI 兼容 coding/v3 | **可直连（同 host 实测）** | 同上（共享 host；G-KEY 覆盖） |
| 火山方舟 · Agent Plan | `ark.cn-beijing.volces.com` | OpenAI 兼容 plan/v3 | **可直连（同 host 实测）** | 同上 |
| 腾讯混元 | `api.hunyuan.cloud.tencent.com` | OpenAI 兼容 | **可直连** | manifest `host_permissions` 覆盖 |
| OpenAI | `api.openai.com` | OpenAI 兼容 | **可直连** | manifest `host_permissions` 覆盖 |
| Claude | `api.anthropic.com` | Anthropic Messages（native） | **可直连** | manifest `host_permissions` 覆盖；native 分支由 base `chat` 处理 |

- **受限/失败处置**：任何厂商端点不可达（网络/密钥/额度/CORS 意外）→ 会话内可读错误 + 厂商处置指引，**不静默失败、不中断会话**（EC-009）；`classifyError` 对 401/403/429/网络分别给出可读原因。
- **回退**：若未来浏览器收紧扩展 fetch 或端点要求页面侧代理，`browserDirect:false` 分支保留可读降级出口（不假装生效）。
- **逐厂商断言**：`test/llm.test.ts` 断言 8 厂商端点 host 均被 manifest `host_permissions` 覆盖（结构化回归）；volc 三端点共享同一 host（G-KEY 实测）。
