## 1. 基础工具清单（源码实测，共 8 个）

pi 内置 **8 个工具**，由 `dist/core/tools/index.js` 的 `allToolNames` 集合确认：`read`、`bash`、`powershell`、`edit`、`write`、`grep`、`find`、`ls`。

**默认只启用 4 个**：`read`、`write`、`edit`、`bash`（见 `createCodingToolDefinitions`）。另有只读子集 `read`/`grep`/`find`/`ls`（见 `createReadOnlyToolDefinitions`，对应 `--tools read,grep,find,ls`）。

> ⚠️ **没有内置 web / webfetch / websearch 工具**。这是 pi 的刻意哲学（README "No MCP"）：联网搜索靠 skill（如 `pi-skills` 的 brave-search）或 extension 补足。这跟 opencode（有 webfetch 无 websearch）一样克制，但 pi 更彻底——连 webfetch 都不内置。

### 文件系统（4 个）
| 工具 | 作用 | 关键参数 | 源码要点 |
|------|------|----------|----------|
| `read` | 读文件内容；文本 + 图片（jpg/png/gif/webp/bmp），图片作为 attachment 返回 | `path`(相对/绝对), `offset`(1-indexed 起始行), `limit`(最大行数) | 文本截断到 **2000 行 / 50KB**（先到为准），超出提示 `offset=N` 续读；图片自动 resize，非视觉模型会附注省略 |
| `write` | 写文件（新建/整体覆盖），自动创建父目录 | `path`, `content` | 走 `file-mutation-queue` 串行化写操作防冲突 |
| `edit` | 精确文本替换（多块一次性替换） | `path`, `edits[]`（每个 `{oldText, newText}`） | `oldText` 必须唯一、互不重叠；匹配前剥离 BOM、统一 LF；返回 `details.diff`(TUI 展示) + `details.patch`(标准 unified patch，供 SDK) |
| `ls` | 列目录，字母序（大小写不敏感），目录带 `/` 后缀，含 dotfiles | `path`, `limit`(默认 500) | 截断到 500 项 / 50KB |

### 内容搜索 / 文件查找（2 个，均依赖外部二进制按需下载）
| 工具 | 作用 | 关键参数 | 源码要点 |
|------|------|----------|----------|
| `grep` | 内容搜索，返回 `文件:行号: 内容` | `pattern`, `path`, `glob`, `ignoreCase`, `literal`(字面量), `context`(上下文行数), `limit`(默认 100) | 底层 `ripgrep`(rg)，`ensureTool("rg")` 缺失时自动下载；尊重 `.gitignore`；长行截断到 500 字符 |
| `find` | 文件 glob 匹配（`*.ts`、`src/**/*.spec.ts`），返回相对路径 | `pattern`, `path`, `limit`(默认 1000) | 底层 `fd`，`ensureTool("fd")`；尊重 `.gitignore`；git 仓库内用 fd 默认 git-aware 行为 |

### 执行（2 个，同一 `createShellToolDefinition` 实现）
| 工具 | 作用 | 关键参数 | 源码要点 |
|------|------|----------|----------|
| `bash` | 执行 shell 命令，流式 stdout/stderr | `command`, `timeout`(秒，可选无默认) | 输出截断到最后 2000 行 / 50KB，超限保存到临时文件（`/tmp/pi-bash-*.log`）；支持 abort 杀进程树；**注入 `PI_*` 环境变量**（`PI_SESSION_ID`/`PI_SESSION_FILE`/`PI_PROVIDER`/`PI_MODEL`/`PI_REASONING_LEVEL`）给子进程 |
| `powershell` | Windows PowerShell 版本 | `command`, `timeout` | 与 bash 共用实现，自动加 UTF-8 输出前缀，仅在 Windows 平台有意义 |

## 2. 权限 / 安全模型（docs/security.md）

pi 的权限模型是**极简、非沙箱**的，核心只有一条：**"以启动它的用户账户权限运行"**。

### 核心原则
- **无内置沙箱**：内置工具（read/write/edit/bash）和 extension（TypeScript 模块）都以 pi 进程的权限运行，可读写文件、执行 shell。
- **刻意为之**：pi 面向本地源码树 + 调用项目工具链。作者认为"进程内半吊子沙箱"容易被误当安全边界（仍依赖 host shell/文件系统/包管理器/凭证/extension 代码），**真正的隔离必须来自 OS 或容器/VM**。
- **无权限弹窗**：README 明确 "No permission popups" —— 要么跑容器，要么用 extension 自己建确认流。

### Project Trust（项目信任，唯一的内置守卫）
这是 pi 唯一的内置安全机制，且**只是"输入加载守卫"**，不是沙箱：

- 当 cwd 出现以下任一"需信任资源"时触发：`.pi/settings.json`、`.pi/extensions|skills|prompts|themes`、`.pi/SYSTEM.md`/`APPEND_SYSTEM.md`、项目 `.agents/skills`。
- 交互模式弹窗询问是否信任；决策存 `~/.pi/agent/trust.json`（按规范化目录，最近父目录决策优先）。
- 非交互模式（`-p`/`--mode json`/`--mode rpc`）不弹窗，按 `defaultProjectTrust`（`ask`=默认忽略 / `always` / `never`）+ `--approve`/`--no-approve` 覆盖。
- **信任前只加载**：context files（AGENTS.md/CLAUDE.md）、用户/全局 extension、CLI `-e` extension；项目本地 extension 和项目 settings 只在信任后加载。
- **明确声明边界**：Project trust 不阻止模型在目录内让工具做任何事，也不防护 prompt injection（仓库文件/注释/文档/构建输出中的注入被视作"本地 agent 固有风险"）。

### 第三方代码风险
- **extension 运行任意代码**、**skill 可指示模型执行任意动作**（含运行可执行文件）、**pi package 以完整系统权限运行** —— README/文档多处红字警告"安装前先审代码"。

### 沙箱推荐做法（containerization.md）
untrusted 仓库 / 无人值守自动化 → 容器/VM/micro-VM/远程沙箱；只挂载任务所需路径、最小化凭证、按需断网。

## 3. 扩展机制（四种，全部无需 fork 源码）

pi 的扩展哲学：**核心最小化，功能通过 extension/skill/prompt/package 外部化**。作者明确砍掉的内置功能：子 agent、plan mode、todo、后台 bash、MCP —— 全部交给扩展层。

### 3.1 Extensions（TypeScript 模块，最底层扩展）
```typescript
export default function (pi: ExtensionAPI) {
  pi.registerTool({ name: "deploy", ... });
  pi.registerCommand("stats", { ... });
  pi.on("tool_call", async (event, ctx) => { ... });
}
```
- **放置**：`~/.pi/agent/extensions/`（全局）、`.pi/extensions/`（项目级，信任后加载）、或 pi package。
- **加载**：经 `jiti` 直接跑 TypeScript，无需编译；工厂函数可 async（await 完成后再继续启动，用于 `registerProvider` 前先取远端模型列表等一次性初始化）。
- **能力面**（`ExtensionAPI` 主要方法）：
  - `pi.on(event, handler)` 订阅 ~30 种生命周期事件（见下）
  - `pi.registerTool()` 注册 LLM 可调用自定义工具（typebox 定义参数，可流式 `onUpdate`，可自定义渲染）
  - `pi.registerCommand(name, {handler})` 注册 `/command`（重名自动加 `:1`/`:2` 后缀）
  - `pi.registerShortcut()` / `pi.registerFlag()` 注册快捷键 / CLI flag
  - `pi.registerProvider(name, config)` 动态注册/覆盖模型 provider（含自定义 OAuth、`refreshModels` 动态发现）
  - `pi.sendMessage()` / `pi.sendUserMessage()` 注入上下文消息 / 伪造用户消息（支持 steer/followUp/nextTurn 投递模式）
  - `pi.appendEntry()` 持久化扩展状态（不进 LLM 上下文，配合 `registerEntryRenderer` 可 TUI 渲染）
  - `pi.exec()` 执行 shell；`pi.setModel()` / `pi.setThinkingLevel()`；`pi.events` 扩展间事件总线
- **事件体系**（可拦截/改造）：`project_trust`、`session_start`/`session_shutdown`、`session_before_switch`/`session_before_fork`/`session_before_compact`/`session_before_tree`（均可 cancel）、`before_agent_start`、`context`（可改消息）、`before_provider_request`/`after_provider_response`、`tool_call`（**可 block 工具，fail-safe**）/`tool_result`（可改结果）、`input`（可拦截/改写输入）等。
- **典型用例**：权限门禁（`rm -rf` 前确认）、路径保护（禁写 `.env`/`node_modules`）、git checkpoint、自定义 compaction、SSH/沙箱执行、MCP 集成（自己做）、甚至跑 Doom 游戏。

### 3.2 Skills（遵循 Agent Skills 标准）
- 自包含能力包：`SKILL.md`（frontmatter + 指令）+ `scripts/`/`references/`/`assets/` 自由组织。
- **渐进式披露**：启动时只把 `name` + `description` 注入 system prompt，任务匹配时 agent 用 `read`/`bash` 按需加载全文。
- **放置**：`~/.pi/agent/skills/`、`~/.agents/skills/`、`.pi/skills/`、`.agents/skills/`（cwd 往上到 git 根）或 package。
- **frontmatter**：`name`(必填，1-64 小写/数字/连字符)、`description`(必填，≤1024)、可选 `license`/`compatibility`/`metadata`/`allowed-tools`(实验)/`disable-model-invocation`(隐藏，仅 `/skill:name` 触发)。
- **调用**：`/skill:name [args]`，args 作为 `User: <args>` 追加。
- **校验宽松**：多数违规只警告不拒绝；`description` 缺失才不加载。

### 3.3 Prompt Templates（可复用 prompt 片段）
- Markdown 文件，`/name` 展开（`name` = 文件名去 `.md`）。
- 支持位置参数：`$1`/`$2`、`$@`/`$ARGUMENTS`、`${1:-default}` 默认值、`${@:N}`/`${@:N:L}` 切片。
- 放置：`~/.pi/agent/prompts/`、`.pi/prompts/` 或 package。

### 3.4 Pi Packages（打包分发）
- 把 extension/skill/prompt/theme 打包成 npm 或 git 包分享。
- `package.json` 加 `pi` manifest 声明资源路径（或约定目录 `extensions/`/`skills/`/`prompts/`/`themes/` 自动发现）。
- `pi install npm:...` / `git:...` / 本地路径；`-l` 项目级安装；支持 glob/`!排除`/`+精确含`/`-精确排` 过滤。
- 依赖：核心包（`pi-ai`/`pi-agent-core`/`pi-coding-agent`/`pi-tui`/`typebox`）用 `peerDependencies`，其余 `dependencies`+`bundledDependencies` 打进 tarball。
- 作用域去重：同一包全局+项目都出现时项目胜出。

## 4. 运行模式（4 种 CLI 模式 + SDK）

| 模式 | 触发 | 说明 |
|------|------|------|
| **Interactive（默认）** | `pi` | 全功能 TUI：编辑器（`@` 文件引用、Tab 路径补全、`!cmd` 执行）、slash 命令、快捷键、消息队列（steer/follow-up） |
| **Print** | `pi -p` | 单次执行，输出响应后退出；可读 stdin 合并进 prompt（`cat README.md \| pi -p "总结"`） |
| **JSON** | `pi --mode json` | 所有 session 事件以 JSON lines 输出到 stdout（`message_update` 为 delta-only，非累积快照，保流式线性） |
| **RPC** | `pi --mode rpc` | 进程集成，stdin/stdout 严格 LF 分隔 JSONL；`prompt`/`steer`/`follow_up`/`abort`/`set_model`/`compact`/`bash` 等命令 + 事件流；**支持 extension UI 子协议**（select/confirm/input/editor 对话框 + notify/setStatus/setWidget 即发即弃） |
| **SDK** | `import { createAgentSession, ... }` | Node.js 内嵌：`createAgentSession()` 工厂、`AgentSession`（prompt/steer/followUp/subscribe）、`AgentSessionRuntime`（new/switch/fork 会话替换）、`ModelRuntime`/`SessionManager`/`SettingsManager`/`DefaultResourceLoader` 等 |

**选型**：SDK 适合同进程/类型安全/直接访问 agent state；RPC 适合跨语言/进程隔离。

## 5. 会话 / 上下文管理

### 5.1 会话存储（sessions.md / session-format.md）
- **JSONL 文件 + 树结构**：每行一个 entry，`id`/`parentId` 链接，支持**原地分支**无需新建文件。
- 存储于 `~/.pi/agent/sessions/--<path>--/<timestamp>_<uuid>.jsonl`（按工作目录组织）。
- 版本 v3（v1 线性 → v2 树 → v3 `hookMessage` 改名 `custom`），旧会话自动迁移。
- **Entry 类型**：`session`(header)、`message`(user/assistant/toolResult)、`bashExecution`、`custom`(扩展状态，不进上下文)、`custom_message`(扩展注入，进上下文)、`model_change`、`thinking_level_change`、`compaction`、`branch_summary`、`label`、`session_info`(会话名)。
- **分支操作**：`/tree`（同文件内跳转）、`/fork`（从早前 user message 开新文件）、`/clone`（复制当前 active branch 到新文件）、`--session`/`--fork` CLI。
- 命名 / 恢复 / 删除：`/name`、`/resume`（可搜索、Ctrl+R 改名、Ctrl+D 删除走 `trash`）。

### 5.2 Compaction（compaction.md）
- **两个机制**：Compaction（上下文超限时压缩旧消息）+ Branch summarization（`/tree` 切分支时总结被弃分支）。
- **自动触发**：`contextTokens > contextWindow - reserveTokens`（默认 reserve 16384）；多轮运行中工具结果 append 后检查。
- **算法**：从最新消息往回走，累计到 `keepRecentTokens`（默认 20000）为 cut point → 收集旧消息 → LLM 结构化总结 → append `CompactionEntry`（含 `summary` + `firstKeptEntryId`）→ 重建上下文（summary + 保留消息）。
- **cut point 规则**：只切 user/assistant/BashExecution/custom 消息，**绝不切 tool result**（必须跟 tool call 在一起）；单轮超限时走 split-turn 双总结合并。
- **结构化总结格式**：Goal / Constraints / Progress(Done/In Progress/Blocked) / Key Decisions / Next Steps / Critical Context + `<read-files>`/`<modified-files>` 标签；累计文件追踪跨多轮压缩保留。
- **可扩展**：`session_before_compact` / `session_before_tree` 事件可 cancel 或提供自定义 summary（含 `serializeConversation()` 工具）。

## 6. 对 web-cli-base 孵化的可借鉴点

| # | pi 设计 | 借鉴价值 |
|---|---------|---------|
| 1 | **8 个工具克制集合 + 默认只给 4 个**（read/write/edit/bash） | 分层工具集：核心最小集 + 可显式追加（grep/find/ls），联网完全外部化 |
| 2 | **edit 用"精确文本替换 + 唯一非重叠约束"**，一次可多块替换，返回 diff + unified patch | 比"字符串替换"更严谨的编辑语义，返回 patch 便于回放/审计 |
| 3 | **工具输出统一截断策略**（read 2000 行/50KB、bash 存临时文件、grep 500 字符/行） | 上下文预算内建到工具层，配合"offset 续读/limit 翻倍"可操作提示 |
| 4 | **grep/find 底层借用 ripgrep/fd + 自动下载 + 尊重 .gitignore** | 不重复造轮子，用成熟二进制保证搜索质量；`.gitignore` 感知是搜索工具必备 |
| 5 | **安全哲学：无内置沙箱，明确声明边界，隔离交给 OS/容器** | 诚实的安全模型：不做"半吊子沙箱"给用户虚假安全感；项目信任只做输入加载守卫 |
| 6 | **扩展四层：extension(代码) / skill(流程) / prompt(片段) / package(分发)** | 能力可插拔的清晰分层；skill 走渐进式披露，只把 description 常驻 context |
| 7 | **事件驱动的 extension API（~30 个可拦截事件，tool_call 可 block）** | 用事件钩子实现权限门禁/路径保护/自定义 compaction，而非框架硬编码 |
| 8 | **会话 = JSONL 树（id/parentId 原地分支）** | 一个文件承载多分支历史，fork/clone/tree 自然；比多文件快照更轻 |
| 9 | **四种运行模式 + SDK 复用同一 AgentSession 核心** | CLI 各模式与 SDK 共享内核，web-cli-base 可直接拿 SDK 起 HTTP 服务 |
| 10 | **RPC 的 JSONL 严格 LF 分帧 + extension UI 子协议** | 进程间集成协议要明确分帧规则（防 Unicode 分隔符坑），UI 交互走请求/响应子协议 |
| 11 | **bash 注入 `PI_*` 环境变量给子进程** | 让 agent 跑的命令能感知 session/model 上下文，利于可观测与工具链协作 |

## 7. 一句话结论

pi 的哲学是**"内核极简 + 扩展激进 + 安全诚实"**：只内置 8 个工具（默认 4 个，**无任何联网工具**），子 agent/plan/todo/MCP 等全部砍掉交给 TypeScript extension + skill + prompt + package 四层扩展；安全上明确"无沙箱、无权限弹窗、项目信任只防静默篡改"，隔离交给 OS/容器；会话用 JSONL 树原地分支，配 compaction/branch-summarization 管理上下文。对 web-cli-base 最值得搬的是 **分层工具集（默认 4 + 可选追加）、edit 精确替换返回 patch、工具层内建截断与 offset 续读、事件驱动可拦截的权限门禁、会话 JSONL 树、SDK/RPC 共享内核**。

> ⚠️ 反例教训：pi 完全不内置 webfetch/websearch，意味着 web-cli-base 若定位"web 优先"需要在工具层补上联网能力（这正是 opencode 有 webfetch 而 pi 没有的关键差异）。
