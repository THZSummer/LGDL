# LGDL AI 实战：9 种图类型全流程演练与视觉模型评审

> 演练方式：**AI Agent（pi）以真实工程师身份，只用 `lgdl-cli` 命令**构建 9 种类型的业务图
> （全程零手写 `.lgdl` 文件），再用**视觉模型（DeepSeek V4-Flash-Vision-Exp）**对渲染结果做
> 业务语义评审。本文记录方法论、9 张示例图与评审结论。
>
> 配套产物：`examples/` 下同名 `.lgdl` / `.svg` / `.png` 三件套。
>
> 另有更早一轮（2026-08-22）针对早期示例图的**渲染质量**评审（布局/连线/配色），
> 见 [README.md](README.md)——与本文档（业务语义维度）互补。

---

## 0. 为什么做这次演练

1. **验证 LGDL 的 CLI 对 AI 的可用性**：AI 只靠 `--help` 能否完成真实业务建模？
2. **验证视觉模型的评审闭环**：图渲染出来后，能否用视觉模型当"免费架构评审"？
3. **沉淀 v0.6 改进线索**：9 张图暴露的共性渲染/校验问题，是"图即代码"套件的输入。

## 1. 方法论（可复现）

```
┌─────────────────────────────────────────────────────────────┐
│ 阶段1 生成（AI 工程师视角）                                    │
│   pi --print "读 task.md 并执行"                              │
│   ├─ lgdl-cli init --file X.lgdl --type <type>  起骨架        │
│   ├─ lgdl-cli add-group / add-node / add-edge ... 逐步构建    │
│   ├─ lgdl-cli status --file X.lgdl                自检        │
│   └─ lgdl-cli render --file X.lgdl -o X.svg      渲染        │
├─────────────────────────────────────────────────────────────┤
│ 阶段2 转位图（视觉模型只吃位图）                              │
│   node svg2png.js   (resvg-js, 1600px 宽, Noto CJK 字体)     │
├─────────────────────────────────────────────────────────────┤
│ 阶段3 评审（视觉模型）                                       │
│   opencode run -m deepseek/deepseek-v4-flash-vision-exp      │
│     "读取 X.png，按 review-X.md 要求给出评审"                 │
└─────────────────────────────────────────────────────────────┘
```

**关键约束（对 AI 生成阶段）**：
- 必须走 CLI 命令，禁止手写 `.lgdl` 文件内容——真实检验命令面是否够用
- 不确定参数先 `lgdl-cli <cmd> --help`——验证自文档化
- 每张图 `status` 自检 + `render` 渲染——验证可迭代

## 3. 评审结论摘要（业务语义维度）

> 每张图按「结构完整性 → 逻辑正确性 → 布局可读性 → 改进建议」评审。
> 以下为每张图**最重要**的发现；完整过程见会话记录。

### 3.1 flowchart — 注册登录流程（`flowchart-auth`）
- ✅ 覆盖注册 → 邮箱验证 → 登录 → 忘记密码 → 会话管理的完整闭环
- ❌ `忘记密码?` 决策菱形只有"是"分支，缺"否"分支 → 分支不闭合
- ❌ `会话有效 → 回环` 疑似忙循环，无心跳/续期语义说明
- ❌ 验证码"重新输入"有，但"重新发送"缺失；无账号锁定/风控
- 💡 **CLI 启示**：可为 decision 节点加结构校验（≥2 条出边），从源头防分支不闭合

### 3.2 mindmap — 产品规划脑图（`mindmap-product`）
- ✅ 中心辐射结构清晰、配色按分支区分
- ❌ "富文本编辑"跨「AI 助手」「文档编辑」重复归属
- ❌ 名为"AI 绘图工作台"却缺画布/图层/文生图等核心绘图分支
- ❌ 中心节点附近连线交叉密集

### 3.3 sequence — 下单时序（`sequence-order`）
- ✅ 下单 → 锁库存 → 支付 → 回调 → 通知五段齐全，含确认回执
- ❌ **无 `releaseStock` 补偿步骤**：锁库存后支付失败/超时，库存永久占用（本图最严重问题）
- ❌ 无超时/重试/幂等标注；`confirmPayment` 让客户端直连支付服务做确认，风险不可控
- ❌ `sendNotification` fire-and-forget，无 ack/死信

### 3.4 uml-class — 订单领域类图（`uml-class-order`）
- ✅ 组合/聚合/关联的区分正确（订单→订单项组合、用户→地址聚合）
- ❌ **收货地址双归属**：订单"配送至"引用 + 用户"拥有"聚合冲突；真实业务应存地址快照
- ❌ `status`/`payMethod` 用 String，应为枚举；`calculateTotal()` 与冗余 `totalAmount` 并存
- ❌ 外键（Long id）与对象引用两种风格混用，未统一

### 3.5 arch — 电商微服务架构（`arch-ecommerce`）
- ✅ 四层（客户端/网关/业务/数据）职责分离正确
- ❌ 服务直连所有数据存储，违背"数据库私有"；订单服务成中心 Hub 单点
- ❌ 缺注册中心/配置中心、分布式事务、缓存一致性策略、可观测性
- ❌ "路由转发"标签重复冗余；异步事件箭头绕大圈

### 3.6 datastream — 实时日志分析（`datastream-log`）
- ✅ 采集 → 传输 → 计算 → 存储 → 应用五层链路成立
- ❌ 缺数据清洗层（脱敏/序列化）、去重（exactly-once 语义）、水位线/乱序处理
- ❌ 告警事件只进 Redis，缺持久化，会丢告警；无离线分层
- 💡 **CLI 启示**：边 attrs 已支持 `processing=filter/aggregate` 等语义标注，可再沉淀为标准约定

### 3.7 er — 订单数据模型（`er-orders`）
- ✅ 主从关系建模完整，29 个字段显式建模
- ❌ 金额无 precision/scale、状态用裸 varchar、普遍缺 `updated_at`
- ❌ 订单无地址快照（地址变更历史不可追溯）、缺 SKU/退款记录/库存流水实体
- 💡 建议 `decimal(12,2)`、受控枚举、FK 与索引显式标注

### 3.8 state — 订单状态机（`state-order`）
- ✅ 主链路（待支付→已支付→已发货→已完成）清晰、终态置底
- ❌ **`已取消 → 已退款` 语义错误**（未支付取消不存在退款）
- ❌ 缺 `退款中` 中间态、超时 `已关闭`、部分退款语义
- ❌ `申请退款` 长斜线横穿全图与发货线交叉
- 💡 **CLI 启示**：状态机合法性校验（源状态×事件×目标状态白名单）可做成命令

### 3.9 gantt — SaaS 迭代排期（`gantt-saas-roadmap`）
- ✅ 按 `--attrs start=<天偏移> duration=<天数>` 声明排期，依赖边表达前后置
- ❌ 纯线性串行，前后端未并行；"部署上线"时长最长不合理
- ❌ **渲染问题：图被压成 1600×183 扁条带**，时间刻度不可读、泳道无分隔线
- 💡 **渲染器启示**：甘特图行高不足是 v0.6 首要布局改进项

## 4. 跨图共性发现 → v0.6 改进清单

| 问题 | 出现图 | 归属 | 定性 | 建议 |
|---|---|---|---|---|
| 连线交叉/标签重叠 | arch、mindmap、er、state、uml-class | render | bug | 布线算法优化（正交布线、文字避让） |
| 决策节点分支不闭合 | flowchart | core/CLI | 需求 | `validate` 增加结构校验（decision ≥2 出边） |
| 状态机非法转移 | state、sequence | core/CLI | 需求 | 状态机合法性校验命令（v0.6 图即代码评审） |
| 甘特图过扁、时间刻度小 | gantt | render | bug | 行高/刻度渲染优化 |
| 重复标签冗余 | arch | render | 渲染增强 | "路由转发"等重复边标签去重 |
| 补偿/失败分支缺失 | sequence、flowchart | 内容层 | 内容层 | 提供业务建模 checklist（AI 提示词模板） |

> 前 3 条 `bug` / `渲染增强` 的**现象、根因、涉及文件与行号、修法**明细见
> [bugs.md](bugs.md)；`需求` 类的决策/状态机校验与 `内容层` 的建模 checklist 见 §5 与 AI 提示词模板范畴。

## 5. 复现要点

- **模型**：生成用 `deepseek-v4-flash`（文本），评审用 `deepseek-v4-flash-vision-exp`（视觉）
- **关键坑**：视觉模型不读 SVG，必须转 PNG（`resvg-js`，本项目 `examples` 的 PNG 即产物）
- **评审要求文件**：每张图配 `review-<name>.md` 引导评审维度，避免模型泛泛而谈
- 沙箱/CI 场景注意：pi/opencode 都需可写 HOME/XDG 目录（本机 `~/.pi`、`~/.local/share` 可能只读）
