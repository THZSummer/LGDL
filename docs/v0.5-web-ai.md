# v0.5.0 设计：Web AI 助手

> 版本主题：**Web 工作台接入 AI 助手**（对话生成/修改图）
> 状态：✅ 已实现（2026-08-23）

## 1. 目标与范围

在现有 Web 工作台（`packages/web`）内嵌 AI 助手，让用户通过自然语言生成新图或修改当前图，AI 输出的 LGDL 一键应用到编辑器并实时渲染。

**范围**（MVP）：

- ✅ 左栏上下分栏布局（编辑器 40% / AI 对话框 60%，分隔条可拖，编辑器可收缩）
- ✅ 对话生成新图 / 修改当前图（当前源码自动注入上下文）
- ✅ 输出 LGDL 代码块 → 「应用」按钮 → 写入编辑器 → 实时渲染
- ✅ 多厂商 API 接入（DeepSeek / Qwen / 火山方舟 / 腾讯混元 / GPT / Claude），用户手动填 key，系统不内置 key
- ❌ 图解释 / 评审 / 选区操作（后续版本）
- ❌ 图即代码（语义 diff、CI 渲染、set-type 等）——推到 v0.6

## 2. 布局改造

当前 `.workspace` 为左右两栏（左编辑器 / 右预览）。改为：

```
+--------------------------------------------+
| header（品牌 + 示例切换器）                 |
+----------------------+---------------------+
| 编辑器 pane（上部 40%）|                     |
| +------------------+ |  预览 pane（不变）    |
| | 分隔条（可拖动）   | |                     |
| +------------------+ |                     |
| AI 对话框（下部 60%）| |                     |
|                     | |                     |
+----------------------+---------------------+
```

- 左栏垂直分割：编辑器（默认 40%）+ AI 对话框（默认 60%），中间分隔条可自由拖动调整比例
- 编辑器可收缩：分隔条拖到最底部自动收起（编辑器折叠为标题栏），点标题栏重新展开
- 右侧预览 pane 布局完全不变
- 实现：flex 布局 + 分隔条 pointer 拖拽，编辑器高度由 `flex-basis` 控制；收缩状态用 state 记录，拖动与收缩互斥（拖拽中不触发收缩，松手后才判定）

## 3. 对话能力（MVP）

### 3.1 交互

- AI 对话框位于左栏下部：消息列表（用户/AI）+ 输入框
- 用户输入自然语言 → 发送 → AI 返回 Markdown（含 LGDL 代码块）
- AI 回复中的 LGDL 代码块右上角有「应用」按钮：
  - 点击后先过 `parseLgdl()` 校验（`validate` 门禁）
  - 合法 → 写入编辑器源码并触发实时渲染（复用现有 compile 流程）
  - 不合法 → 在代码块上标红显示校验错误，不写入（符合「有损必警告」原则）

### 3.2 上下文注入

每次请求自动拼接 system prompt + 当前图上下文：

```
system: LGDL 语言规范摘要（结构、字段、kind 枚举、约束、示例片段）
user:   [当前源码]（若编辑器非空）
        用户指令：<自然语言>
```

- 当前源码从编辑器读取（`source` state）
- 生成新图：提示 AI「输出完整 LGDL 文档」
- 修改当前图：提示 AI「基于上方当前源码输出修改后的完整文档」（整图重写式修改，MVP 不做增量 diff——增量编辑协议仍是 CLI 的强项，Web AI 助手侧重自然语言生成）

### 3.3 校验门禁（validate 门禁）

AI 输出应用前必须通过：

1. `parseLgdl(source)` → `result.valid` 必须为 true
2. 通过后写入编辑器，现有 linter/渲染链路自动工作（错误标红、实时预览）
3. 若失败：展示 `result.issues`（含 location 定位），提示用户修正或让 AI 重试

## 4. Provider 层（多厂商 API）

### 4.1 原则

- **系统不内置任何 apiKey**，只允许用户手动输入
- key 存 `localStorage`（仅本地使用，不上传）
- 默认支持常见厂商，可扩展

### 4.2 厂商接入

| 厂商 | baseURL | 适配 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | openai SDK |
| Qwen（阿里百炼） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | openai SDK |
| 火山方舟 Ark | `https://ark.cn-beijing.volces.com/api/v3` | openai SDK |
| 腾讯混元 | `https://api.hunyuan.cloud.tencent.com/v1` | openai SDK |
| GPT (OpenAI) | `https://api.openai.com/v1` | openai SDK |
| Claude (Anthropic) | 原生 Messages API | `@anthropic-ai/sdk` |

- 统一抽象：`ProviderConfig { id, name, baseURL, apiKey, model }`
- openai SDK 浏览器直连需 `dangerouslyAllowBrowser: true`（官方支持）
- Claude 单独分支走 `@anthropic-ai/sdk`
- 厂商列表可在设置面板选择；model 默认值按厂商预填（如 deepseek-chat / qwen-plus / doubao-… / hunyuan-… / gpt-4o-mini / claude-3-5-haiku），允许用户覆盖

### 4.3 错误处理

- CORS 失败 / 网络错误 / 401（key 无效）→ 明确的错误提示，区分「key 无效」「网络不通」「厂商 CORS 不允许」三种情况
- 请求超时 / 输出为空 → 提示重试
- 流式输出（SSE）：MVP 先做**非流式**（完整返回），流式列入后续优化

## 6. 风险与验证

- **CORS**：OpenAI 官方支持浏览器直连；DeepSeek 实际可直连；火山/腾讯需实现时实测，不通则给出明确报错（符合「有损必警告」）
- **输出质量**：AI 生成 LGDL 依赖规范提示词质量，用现有示例（EXAMPLES）做回归验证——生成结果必须通过 `validate()` 且渲染不报错
- **key 安全**：只存 localStorage、不上传、不写日志；README 明确说明风险由用户自担
