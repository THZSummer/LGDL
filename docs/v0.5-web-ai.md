# v0.5.0 设计：Web AI 助手

> 版本主题：**Web 工作台接入 AI 助手**（对话生成/修改图）
> 状态：✅ 已实现（2026-08-23）

## 1. 目标与范围

在现有 Web 工作台（`packages/web`）内嵌 AI 助手，让用户通过自然语言生成新图或修改当前图，AI 输出的 LGDL 一键应用到编辑器并实时渲染。

**范围**（MVP）：

- ✅ 左栏上下分栏布局（编辑器 40% / AI 对话框 60%，分隔条可拖，编辑器可收缩）
- ✅ 对话生成新图 / 修改当前图（当前源码自动注入上下文）
- ✅ 输出 LGDL 代码块 → 「应用」按钮 → 写入编辑器 → 实时渲染
- ✅ 多厂商 API 接入（DeepSeek / Qwen / 火山方舟 / 腾讯混元 / GPT / Claude），用户手动填 key，系统不内置 key
- ❌ 图解释 / 评审 / 选区操作（后续版本）
- ❌ 图即代码（语义 diff、CI 渲染、set-type 等）——推到 v0.6

## 2. 布局改造

当前 `.workspace` 为左右两栏（左编辑器 / 右预览）。改为：

```
+--------------------------------------------+
| header（品牌 + 示例切换器）                 |
+----------------------+---------------------+
| 编辑器 pane（上部 40%）|                     |
| +------------------+ |  预览 pane（不变）    |
| | 分隔条（可拖动）   | |                     |
| +------------------+ |                     |
| AI 对话框（下部 60%）| |                     |
|                     | |                     |
+----------------------+---------------------+
```

- 左栏垂直分割：编辑器（默认 40%）+ AI 对话框（默认 60%），中间分隔条可自由拖动调整比例
- 编辑器可收缩：分隔条拖到最底部自动收起（编辑器折叠为标题栏），点标题栏重新展开
- 右侧预览 pane 布局完全不变
- 实现：flex 布局 + 分隔条 pointer 拖拽，编辑器高度由 `flex-basis` 控制；收缩状态用 state 记录，拖动与收缩互斥（拖拽中不触发收缩，松手后才判定）

## 3. 对话能力（MVP）

### 3.1 交互（命令模式 —— AI 不直接写源码）

- AI 对话框位于左栏下部：消息列表（用户/AI）+ 输入框
- 用户输入自然语言 → 发送 → AI 返回 Markdown（含 **```bash lgdl 命令块**）
- AI 像在 Linux 终端里一样用 `lgdl` 命令操作图（`lgdl status` / `lgdl add-node --id x --label y` …），**不直接输出 LGDL 源码**——源码只能由命令执行产生
- AI 回复中的命令块右上角有「执行」按钮：
  - 逐条解析（`core/web-cli.ts`，与 CLI 命令同语义）→ `applyOperations` 应用到当前编辑器源码 → `validate` 门禁 → 写入编辑器实时渲染
  - status 命令输出当前图结构文本（`formatStatus`），供 AI 与用户理解图
  - 任一条失败即停，红框展示失败原因（失败即停与 CLI 一致）

### 3.2 上下文注入

每次请求自动拼接 system prompt + 当前图上下文：

```
system: LGDL 命令规范（可用命令、参数、使用流程、硬性约束）
user:   [当前源码]（若编辑器非空，供 AI 理解图；AI 不得输出源码）
        用户指令：<自然语言>
```

- 当前源码从编辑器读取（`source` state），注入供 AI 理解，但 system prompt 明确禁止 AI 输出源码块（只允许 ```bash 命令块）
- 生成新图：AI 先 `lgdl status`（空图提示）再逐条 add-node / add-edge 搭建
- 修改当前图：AI 先 `lgdl status` 读图，再增量命令修改

### 3.3 校验门禁（validate 门禁）

命令执行后必须通过：

1. 每条命令解析失败即停（`parseCommandBatch`）
2. `applyOperations` 执行失败即停，返回已执行部分
3. 结果 `validate()` 通过后序列化写入编辑器，现有 linter/渲染链路自动工作
4. 失败：红框展示失败命令 + 原因，提示用户修正或让 AI 重试

### 3.4 命令与 CLI 的一致性

- `core/web-cli.ts` 把 `lgdl <subcommand> --key value` 文本解析为 `LgdlOperation`
- 支持 9 个增量命令 + status，参数名/必填/校验与 packages/cli 完全一致
- CLI 与 Web 共用同一 `applyOperation`/`applyOperations` 执行层

### 3.5 web-cli 通讯协议（表达 vs 执行）

AI 与工作台之间定义**标准协议**，明确区分"说话"与"执行"：

| 载体 | 语义 | 是否执行 |
|---|---|---|
| 普通文本 | chat 表达（解释/计划/总结） | ❌ 不解析不执行 |
| ```` ```lgdl-web-cli ```` 代码块 | **web-cli 执行调用**（每行一个 `lgdl <子命令> --key value`） | ✅ 解析并逐条执行 |
| 其他代码块（bash/code/yaml…） | 视为普通文本 | ❌ |

- AI 不直接写 LGDL 源码——源码只能由 `lgdl-web-cli` 调用执行产生
- 执行结果（status 输出 / ✓ 摘要 / ✖ 错误）以 **tool 消息**（终端样式）反馈回对话，并作为下一轮 LLM 上下文（映射为 user 角色 + `[web-cli 执行结果]` 前缀）
- **agent 循环**：每轮 AI 输出 1~3 条调用 → 执行 → 结果反馈 → AI 继续，直到总结收尾或达到 10 轮上限；失败会反馈给 AI 让其修正（终端体验）
- 协议实现在 `web/ops.ts`（`extractCommands` 只认 lgdl-web-cli 围栏）+ `core/web-cli.ts`（解析）+ `applyOperations`（执行）

## 4. Provider 层（多厂商 API）

### 4.1 原则

- **系统不内置任何 apiKey**，只允许用户手动输入
- key 存 `localStorage`（仅本地使用，不上传）
- 默认支持常见厂商，可扩展

### 4.2 厂商接入

| 厂商 | baseURL | 适配 |
|---|---|---|
| DeepSeek | `https://api.deepseek.com` | openai SDK |
| Qwen（阿里百炼） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | openai SDK |
| 火山方舟 Ark | `https://ark.cn-beijing.volces.com/api/v3` | openai SDK |
| 腾讯混元 | `https://api.hunyuan.cloud.tencent.com/v1` | openai SDK |
| GPT (OpenAI) | `https://api.openai.com/v1` | openai SDK |
| Claude (Anthropic) | 原生 Messages API | `@anthropic-ai/sdk` |

- 统一抽象：`ProviderConfig { id, name, baseURL, apiKey, model }`
- openai SDK 浏览器直连需 `dangerouslyAllowBrowser: true`（官方支持）
- Claude 单独分支走 `@anthropic-ai/sdk`
- 厂商列表可在设置面板选择；model 默认值按厂商预填（如 deepseek-chat / qwen-plus / doubao-… / hunyuan-… / gpt-4o-mini / claude-3-5-haiku），允许用户覆盖

### 4.3 错误处理

- CORS 失败 / 网络错误 / 401（key 无效）→ 明确的错误提示，区分「key 无效」「网络不通」「厂商 CORS 不允许」三种情况
- 请求超时 / 输出为空 → 提示重试
- 流式输出（SSE）：MVP 先做**非流式**（完整返回），流式列入后续优化

### 4.4 CORS 实测结论（2026-08-23）

浏览器直连依赖厂商 CORS 预检允许认证头。实测：

| 厂商 | 预检结果 | 浏览器直连 |
|---|---|---|
| DeepSeek | 允许 `authorization,content-type` | ✅ |
| Qwen（阿里百炼） | 允许 `authorization,content-type` | ✅ |
| 腾讯混元 | 返回 allow-origin + allow-headers | ✅ |
| OpenAI / Anthropic | 官方 SDK 支持浏览器 | ✅ |
| 火山方舟（通用/Coding/Plan） | 仅 `Origin,Content-Length,Content-Type`，认证头被拦 | ❌ |

- 配置面板对不可直连厂商（火山三个套餐）显示 ⚠ 警告并禁用测试/发送
- 「测试连接」按钮：配置时发最小请求验证 key/端点/CORS
- 火山等受限厂商需本地代理（`lgdl serve`）——列入 v0.6

## 6. 风险与验证

- **CORS**：OpenAI 官方支持浏览器直连；DeepSeek 实际可直连；火山/腾讯需实现时实测，不通则给出明确报错（符合「有损必警告」）
- **输出质量**：AI 生成 LGDL 依赖规范提示词质量，用现有示例（EXAMPLES）做回归验证——生成结果必须通过 `validate()` 且渲染不报错
- **key 安全**：只存 localStorage、不上传、不写日志；README 明确说明风险由用户自担
