## 2. 上下文与边界

### 2.1 上下文

父规范 §2.3 根因 **G**（逐条授权链路：`security/confirm.ts:84-156` 单条摘要 + 审计 → `service-worker.ts:634-644` `confirm-request` → 面板 `sidepanel.ts:3837-3845` → **既有 `auth` 卡** `chat-state.ts:616-622`）、根因 **M**（红线⑥ 可机核：`test/supersession-ledger.test.ts:2266,2339-2347` + `test/op-three-tier.test.ts:332,372-383`；特权 op `ops.ts:24,307,317` + `test/capability-wiring.test.ts:51-58`）、根因 **R**（法八四面 `test/ui/law8-plaintext.mjs:56-61,231,383`；`cards/auth.ts` 头注释：预演 = **静态三段模板**）全部落在本叶 + §2.4 C 面（C1~C6）。

**本叶要解决的问题**（真机实测，`ty.md`）：**42 调用 / 42 卡 / 42 批准 / 理由串逐字相同**（§2.2 S1~S5）⇒ 授权从**判断**退化为**连点**：用户看不到「整批将要写什么」，**无法在写之前否决计划本身**；`auth` 卡每张都「合法」，于是**恰好掩盖了范围漂移**。本叶的验收锚 = **一次手势覆盖计划指纹，计划外逐条回落，且不得成为「AI 代答 consent」的合法外衣**（R-SGO-001，唯一红线级）。
