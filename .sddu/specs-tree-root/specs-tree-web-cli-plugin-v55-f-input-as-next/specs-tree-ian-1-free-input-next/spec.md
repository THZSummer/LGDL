## 2. 上下文与边界

### 2.1 上下文

父规范 §2.2~§2.5 的**新面根因**全部落在本叶：「自由输入」作为 next 选项的形态缺位（`Q-IAN-003`）；next 注册表已是可注册 provider/chip（`next-registry/registry.ts` / `providers.ts`；`MAX_CHIPS_PER_CARD = 3`）但**无**自由输入 provider；卡内输入先例现成（`askuser.ts:71-86,263-300`）；`op.turn` = 唯一回合发起通道（`ops.ts:29-35`「`op.turn` is the ONLY `requestTurn` caller」）；`requestTurn` 定义 `sidepanel.ts:313`、调用点恰 2（`:3756` composer submit + `:3783` op.turn 槽）；R6 有界队列语义与输入面位置解耦（`turn-queue.ts`）；`op.turn` ∈ `auto` 档（`op-table.ts:134`）。

**本叶的验收锚**：把「想自由输入」这一最基本的用户意图**搬进流内 next 闭环**，且**在旧 composer 入口仍可用的前提下**（中间态保护）—— 使「先立新面」这一步**不破坏现网行为**。
