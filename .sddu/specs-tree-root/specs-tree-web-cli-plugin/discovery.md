- **版本位重排**：原 v0.8.0「工程质量与文档对齐」→ v0.9.0；原 v0.9.0「AI 增强与生态」→ v0.10.0；v1.0.0 不变（时间窗口待复核）；**v1.1.0 = 仅 F-13 ②（web-cli 开源）**，F-14 移出（ROADMAP :36-40、:296）。
- **F-14 性质**：作者规划/作者指令（非审视池项），可作规划承诺；**技术细节（协议发现机制 / 插件架构）不预设立场**，留给未来立项（ROADMAP :17、:212-214、:216）。

- **已登记风险**：风险 11（协议发现标准缺失，🟡 中）、**风险 12（LLM 直接操作网页的安全/合规边界，🔴 高）**、风险 13（跨域与浏览器扩展平台限制，🟡 中）（ROADMAP :519-521）。

## 1. 问题定义

> 概括核心问题及其业务影响，回答"为什么需要关注"

| 核心问题 | 业务影响 | 不解决的成本 |
|---------|---------|------------|
| **内置 AI 助手被锁在 LGDL 页内**：它只能在宿主应用自身同源页面操作（v4 discovery D-2/D-3、:43-44、:85），无法操作 LGDL 之外的任何网站，也无法触达浏览器外壳能力 | web-cli 生态只能服务单一站点；「任何支持 web-cli 协议的网站都能被 AI 驱动」的产品主张落空 | v0.8 主题无法成立；web-cli-base 的通用框架价值被单站点消费端封顶 |
| **「替代内置 AI 助手」的准确语义未界定**：内置助手已具备完整工具集与编辑器状态直连（session.ts:269-354、:92-119），插件作为独立扩展无法天然取得 React 应用内部状态 | 替代命题（作者 2026-09-10 原话）缺乏可执行定义，spec 无法定边界 | 范围失控或替代失败（做了插件但替代不了内置助手） |
| **网站无统一「声明支持 web-cli」机制**：当前只能逐站点定制，无发现/声明协议 | 插件无法规模化覆盖任意站点，生态价值落空（ROADMAP 风险 11） | 插件沦为「LGDL 专用注入脚本」，与「独立于 LGDL 的插件」定位矛盾 |
| **LLM 按 key 驱动网页执行操作的安全/合规边界未定义**：越权操作、敏感数据外泄、账号风控、站点自动化条款冲突（ROADMAP 风险 12，🔴 高） | 插件形态下用户不敢授权、站点不敢接受；合规风险不可控 | 高风险面不先解决则插件无法真实启用 |
| **插件载体（浏览器扩展）能力边界与页内 web-cli-base 的关系未定义**：MV3 content script 隔离 / CSP / 跨域 / 权限最小化（ROADMAP 风险 13） | 插件架构无从落地，页内已有的一份 CommandRouter 与插件关系不明 | 重复建设 / 双份工具面冲突 / 平台约束导致方案返工 |
