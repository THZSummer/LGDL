## 2. 上下文

### 2.1 要解决的问题（discovery 问题清单主干）

作者立项口径（discovery §0.1）：**「提供浏览器插件，web-cli-plugin，配置完大模型的 key 之后，就支持借助打开的网站的 web-cli 完成业务」**（2026-09-01）+ **「孵化浏览器插件，独立于 LGDL 的一个插件，可以适用于 LGDL 的 Web 页面，替代现有的 AI 助手」**（2026-09-10）。ROADMAP v1.12.0 将 F-14 由 v1.1 提前至 v0.8 作该版主题。

discovery §1/§3 确认本 Feature 的核心问题（Q-001~Q-008）与业务影响：

- **Q-001「替代内置 AI 助手」语义未界定**：内置助手是与 React 应用深度耦合的会话组装点（`session.ts:262` `createAiSession`，注入 `docId`/`getSource`/`onApply`/`opRegistry`/`settings`；已注册 20+ 工具），插件作为独立扩展**无法天然取得应用内部状态**。三种语义（功能替代 / 入口替代 / 代码下线）对边界影响完全不同。
- **Q-002 同源锁死**：内置助手全部 DOM 读/写/evaluate 目标 = 宿主应用自身同源页面（`session.ts:273-284`；v4 discovery D-3/NG-002），无法操作 LGDL 之外的任何站点——「任何支持 web-cli 协议的网站都能被 AI 驱动」的产品主张落空。
- **Q-003 CORS 限缩 BYOK**：8 厂商中火山方舟 3 端点 `browserDirect=false`（`provider.ts:54-56`），浏览器直连被拦；缓解承诺「本地代理 `lgdl serve`」**未实现**（ROADMAP:16 如实标注）。
- **Q-004 浏览器外壳能力整体不可达（12 项）**：多标签/窗口、下载管理、整页截图、HttpOnly/跨域 cookie、DevTools 全局面网络、跨导航持久订阅、closed shadow、跨域 iframe、原生对话框、真受信输入、权限真模拟、file 真路径注入——页内均不可达（`ext-attribution.ts:39-136` ATTRIBUTION_MAP）。
- **Q-005 站点级 web-cli 协议发现/声明机制不存在**：全仓 grep 0 命中；`protocol.ts:11` 仅为 CLI 命令 tokenize/parse，与站点协议无关。插件无法规模化覆盖任意站点（ROADMAP 风险 11）。
- **Q-006 协议信任另一半未定义**：现有 PRM 信任模型只覆盖「消费端本地注册的工具」（`permission.ts:34` ToolRisk、:169-171 defaultActionForRisk），**无第三方声明面**；恶意/被篡改站点可否声明危险工具（write/evaluate/external）并诱导 AI 执行未定义。
- **Q-007 MV3 载体边界与页内 web-cli-base 关系未定义**：content script 隔离 / 站点 CSP / 跨域 / 权限最小化（ROADMAP 风险 13）；插件与页内已运行的 `web-cli-base`（`platform.ts:692-731`）是复用/桥接/并存/接管何种关系未定；当前全仓零扩展工程痕迹。
- **Q-008 LLM 驱动网页执行的安全/合规边界未定义（🔴 高）**：越权操作、敏感数据外泄、账号风控、站点自动化条款冲突（ROADMAP 风险 12）。现有安全模型（PRM 门禁 + untrusted + 脱敏 + 审计）是**页内消费端**模型，插件形态下的用户授权模型 / 敏感操作二次确认 / 可审计性未定义。

**业务影响**：web-cli 生态只能服务单一站点，「任意 web-cli 站点可被 AI 驱动」的产品主张落空；安全/合规面不先解决则插件不敢真实启用、站点不敢接受（R-001）；载体与协议机制不定义则插件架构无从落地（R-002/R-003）。

### 2.4 与上游基线的衔接（代码事实，v0.7.0 已发布稳定）

> **更正 discovery R-006（已过时）**：v0.7（web-cli-base v2/v3/v4）**已于 2026-09-10 合入 main 并发布 npm 0.7.0**（tag `v0.7.0` 已打）。本 Feature 可将其作为**已发布稳定基线**引用，不再存在「基于未发布基线开发」的漂移风险（R-006 解除）。

- **web-cli-base v0.7.0（框架层，零 LGDL/react 依赖）**：`CommandRouter`（ToolEntry 统一注册条目：schema/executor/prefix/help/order/delay/group/namespace/enabled/risk/subcommandRisks，`router.ts:63-96`）+ `AgentRunner`（中性 agent 循环）+ `DelayGate`（全局 delay）+ 九域浏览器原生工具集（DOC/STR/SRC/NET/DOM·UI/EXE/TSK/EXT/会话上下文）+ `PermissionGate`（裁决管线：allowed-tools → 规则集 → 策略对象 → 缺省取向，deny 优先；`permission.ts`）+ `AuditSink` + 事件 push/缓冲/订阅通道（`event-bus.ts` + `env.events` + `events` 工具）+ 敏感字段模型（`sensitive.ts`）。
- **LGDL 领域适配层**：`@lgdl/lgdl-web-cli`（图内容操作 9 增量命令）+ `@lgdl/lgdl-web-op-cli`（UI 操作）——本插件在 LGDL 站点需对齐的能力面来源。
- **内置助手（被替代对象）**：`packages/lgdl-web/src/ai/session.ts` 单一组装点（`createAiSession` 注入 `docId`/`getSource`/`onApply`/`opRegistry`/`settings`；`AiPanel`/`AskDialog`/`SettingsPanel`；`provider.ts` 多厂商 BYOK 8 厂商，key 存 `localStorage`）。
- **ATTRIBUTION_MAP（12 项契约预留，`ext-attribution.ts:39-136`）**：v4 已把「需扩展/系统级」能力（多标签/窗口、下载、整页截图、HttpOnly·跨域 cookie、DevTools 全局面网络、跨持久订阅、closed shadow、跨域 iframe、原生对话框、真受信输入、权限真模拟、file 真路径注入）逐项映射到「归属宿主 + 扩展 API/CDP 域 + 契约预留建议」——**本 Feature 是这些能力的实际承接方**（v4 FR-026 明确「仅供 F-14 立项继承/修订，非承诺」）。
- **零扩展工程痕迹**：当前全仓无 `manifest.json`/MV3/content script/background（grep 0 命中）——插件运行时为**全新工程领域**（R-002）。

## 3. 目标与非目标

### 3.1 目标 (Goals)

| # | 目标描述 |
|---|---------|
| G-001 | **通用任意站点优先的端到端闭环（O-002）**：在**任意**声明支持 web-cli 的站点上，用户配置 LLM key → 对站点显式授权 → AI 借助站点 web-cli 完成业务——「打开站点即用」的通用消费端成立，LGDL Web 页是其中一个实例而非唯一目标 |
| G-002 | **web-cli 协议发现/声明机制从 0 到 1（O-002/O-003）**：建立「站点如何被发现支持 web-cli、如何声明暴露的工具面、声明如何被信任」的最小语义与验收边界（**不预设格式**），并完成最小试点验证 |
| G-003 | **安全/授权/审计基线先行（O-008/O-009/O-010）**：per-origin 显式授权 + 敏感操作二次确认 + 全程可审计 + 只读/幂等默认 + 站点声明默认 untrusted + 危险档位强制确认 + **fail-closed（不静默 allow）**——高风险面启用前提（R-001） |
| G-004 | **合规评估先行（O-009）**：站点自动化条款合规评估、用户知情告知、合规边界文档化——插件在真实站点可用前的合规门槛 |
| G-005 | **替代内置助手并具备下线条件（O-001）**：插件能力对齐到「可安全下线内置助手」的验收门槛（Gate-D，§9.5），并给出代码下线执行与存量迁移路径；**「替代 = 代码下线」为作者裁决** |
| G-006 | **上游基线 additive 复用与独立边界**：复用 web-cli-base v0.7.0 机制层（不重写框架）、插件独立于 LGDL（独立包/独立构建产物、零 LGDL 私有依赖），同时可作用于 LGDL Web 页面 |
| G-007 | **范围可裁剪、容量可控（R-004 缓解）**：以波次/最小可用切分承载（§9.5），明确 P0 必做与可后置项，供作者裁剪——避免「插件运行时 + 协议机制 + 能力对齐 + 安全 + 迁移」单版本全量膨胀 |
| G-008 | **平台约束可验收（R-002）**：以需求形式表达 MV3 平台约束（权限最小化 / content script 隔离 / CSP·跨域能力边界）并设最小验证门，降低架构返工风险 |

### 3.2 非目标 (Non-Goals)

| # | 明确不做 |
|---|---------|
| NG-001 | **不重写 web-cli-base 框架**：插件复用既有机制层（CommandRouter/AgentRunner/DelayGate/PermissionGate/AuditSink/事件通道/工具契约），不做破坏性重构；上游既有能力行为零回归 |
| NG-002 | **不在本 Feature 内固化协议格式/插件架构方案**：协议发现/声明的**格式形态**、插件技术栈选型、权限模型实现细节、目录/构建拓扑 = **plan 职责**；本规范只定义需求与验收边界（作者明确「技术细节不预设立场」，ROADMAP:17/:212-214） |
| NG-003 | **不做 OS 生态位能力**（系统级截图/真 shell/本地文件树/进程守护）→ 未来 os-cli-base（v4 NG-001 延续） |
| NG-004 | **不承诺 CDP 级真受信输入/权限真模拟/响应伪造**（`ext-attribution.ts` 归属 CDP 生态位项）——是否首版纳入见 O-012/FR-022 待裁；默认按「插件天然可达子集」取舍 |
| NG-005 | **不启动 F-13 ② 开源决策**（许可/命名/仓库名/发布管道）→ v1.1 线；本 Feature 仅保持协议中立、预留标准化接口（S-013，不承诺） |
| NG-006 | **不自动迁移存量配置**（S-015 暂定基线，待核签）：首版不自动迁移内置助手 key/模型/设置，提供手动重配指引 |
| NG-007 | **不在本 Feature 捆绑修复内置助手已知缺陷**（R-D2 分组定位断裂 / W-D1 web-fetch 不可达 / W-D3 preview-click 假成功）——S-014 暂定基线（待核签），除非阻塞插件线 |
| NG-008 | **不做多标签/跨标签并发会话**（S-011 暂定基线，待核签）：首版单标签绑定（当前活动标签），多标签/跨标签归后续 |
| NG-009 | **不做商店发布**（S-016 暂定基线，待核签）：首版本地 unpacked 加载 + 自托管/未打包分发，商店发布后续 |
| NG-010 | **不承诺「插件不可用时的无缝回退」**：内置助手代码下线为作者裁决的不可逆方向，回退风险由 MIG 组 FR-037/038 的下线门槛与执行纪律控制（不做双份长期并存） |

#### 9.5.1 Feature 拆分建议（仅建议，不执行）
