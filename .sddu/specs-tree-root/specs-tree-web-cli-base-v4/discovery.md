## 1. 问题定义

### 1.1 Feature 定位与公理（v4 立项指令，2026-09-07，作者原话口径）

沿用 v2/v3 立项公理：
- **A1 场景完备性**：「人类日常操作浏览器的完整场景，理论上都应有对应工具给 AI」——凡人类能对浏览器做的，web-cli-base 都应提供工具。
- **A2 F12/爬虫等效性**：凡人类靠 F12 开发者工具或爬虫才能做的，web-cli-base 也应提供等价工具。

v4 新增两条**核心分界命题**（作者强调，2026-09-07 指令口径）：
- **P1（推送面缺失命题）**：当前架构 = request→response，无 push/订阅通道——事件监听/观察流（DOM 事件、页面生命周期、网络/console 观察）这类「持续发生、需主动推给 AI」的能力**整体无法表达**，与 v2/v3 全部「拉式」工具形态存在结构性差异。
- **P2（载体分界命题）**：部分能力（标签/窗口/下载/整页截图/DevTools 级网络拦截等「浏览器外壳/浏览器级」能力）**网页 JS 无法直接操作浏览器**——作者明确：这些能力**仍全部纳入 v4 梳理输入范围**，未来**可能通过提供浏览器扩展（browser extension）来实现**。

> 由 P2 派生 v4 问题域主问题：**「AI 帮人类操作浏览器」的边界从「页面内」延伸到「浏览器外壳」时，载体（网页内 JS vs 浏览器扩展）如何分层、扩展线以何形态引入、对 v2/v3 既有契约的影响是否 additive——均未定义**（见 §5）。

### 1.3 核心问题与业务影响

| 核心问题 | 业务影响 | 不解决的成本 |
|---------|---------|------------|
| **push/订阅通道缺失（P1）**：事件监听/观察流（DOM 事件、页面生命周期、网络/console 观察）要求「持续事件推给 AI」，与 v2/v3 request→response 架构形态不兼容——11 项中能力 1、4 的观察面整体不可表达（Q-001） | AI 无法「感知-响应」：等用户输入完成、等页面导航/崩溃、等网络失败只能靠 sleep+snapshot 轮询猜测；无人值守自动化遇模态框/事件驱动流程即卡死 | 自动化可靠性停留在「猜时序」；事件驱动的人类日常场景（表单补全继续、登录后继续、SPA 跳转跟随）全部不可委派 |
| **浏览器外壳不可达（P2）**：标签/窗口/下载管理/整页截图等浏览器级能力在网页内无 API，v3 已判 out 归 F-14 扩展宿主——但「扩展」这一新架构线（形态、与 browserEnv 关系、对既有契约影响）**完全未定义**（Q-002/Q-008/Q-009） | AI 只能操作「当前这一个标签、这一页」；多标签对比/新开标签/下载管理/跨页任务不可表达 | A1 公理在浏览器外壳场景落空；能力边界悬在「页面不可承载就 out」，没有第二条腿 |
| **网络层观察/拦截缺环**：页面自身发出的请求（URL/状态/响应头/失败）AI 不可见；无请求观察/拦截（DevTools Network 等效）（Q-003） | AI 排障（「这个接口为什么 500」「请求带没带 header」）不可表达；对宿主页网络行为无感知 | A2（F12 等效）在网络面板场景落空；排障/拦截自动化整段缺 |
| **若干「判死项」未解冻即不可表达**：file input 上传（NG-004 判死）、cookie 读写/删除、对话框处理、权限模拟等——其中部分在页内有（受限的）可达路径，但被 v3 以「不可承载」整体记 out，无分界（Q-004/Q-005/Q-006） | AI 无法帮用户上传文件、无法处理 alert/confirm、无法判断登录态 cookie | 「表单完整生命周期」（填→传→交）、「对话框自动化」等人类高频场景断链 |
| **载体分层未定义导致的能力归属混乱**：同一能力（如网络观察、文件上传、剪贴板富内容、touch、shadow/iframe 穿透）实际是「页内可达一部分 + 需扩展一部分」的分层体，v3 以单值 out/可承载记录（Q-008） | 下游 spec/plan 无法判断每项该落到哪个实现面；页内可达的「快赢面」与需扩展的「长线面」被一锅判死或一锅放开 | 范围决策（O-001/O-003）无依据；后续返工风险 |

### 3.3 11 项候选能力逐项排查（问题挖掘：场景/痛点，而非功能清单）

> 列：**用户真实场景与痛点（问题域叙述）** / **候选用户故事（问题域表述，非需求）** / **现有状态（证据）** / **浏览器可达性事实（知识面，待最小验证）** / **载体初判**。
> 载体初判图例：🟢=网页内可达（当前架构或 Web API 可达）｜🔴=需浏览器扩展（网页内不可达）｜🟡=分层体（页内可达一部分 + 需扩展一部分）｜🟠=待定（可达性依赖验证/作者裁决）。

#### C-01 事件监听/观察流（DOM 事件流 + 页面生命周期 + 网络/console 观察）

| 维度 | 内容 |
|------|------|
| 用户真实场景与痛点 | ①AI 让用户做一件事（如「请在弹出的输入框输入你的密码，完成后我继续」）后，**无法知道用户何时完成**——现在只能 sleep 猜延时再 snapshot，用户快/慢都错位；②AI 触发导航/SPA 路由跳转后，**不知道新页面何时 ready**（v3 的 wait 是「AI 主动等元素」，不是「页面主动通知」）；③宿主页即将卸载/reload 时（v3 reload 默认 ask 正是因上下文中断），AI **无生命周期感知**，无法先保存状态；④页面自己发出的 console 报错/网络失败，AI **无从得知**（只能等用户报告）。痛的本质：**人类操作浏览器是事件驱动感知-响应，AI 只能轮询拉取** |
| 候选用户故事 | 作为 AI 操作者，我需要在「用户完成页面操作/页面发生导航/出现 console 错误」时**被通知**，而不是反复 sleep+快照猜测；作为 AI 操作者，我需要在宿主页 reload/导航前收到生命周期事件以便保存会话状态 |
| 现有状态 | waitFor = MutationObserver 拉式等待（platform.ts:260，FR-025）；reload 破坏性语义已记录（FR-027）；**无任何事件推送通道**（§3.1 grep 0 命中） |
| 浏览器可达性事实 | DOM 事件监听（addEventListener）/生命周期（visibilitychange/pagehide/beforeunload/Navigation API）/console 捕获（patch console.*，同 realm）**页内可达**；MutationObserver 可观察 DOM 变化。**跨导航持久性受限**：旧文档监听器随导航销毁，续接需宿主会话恢复机制（页内 sessionStorage/IDB 可辅助，但「推给 AI」通道本身不存在）。PerformanceObserver（resource timing）页内可达但受 CORS/TAO 限制（完整请求级观察见 C-04） |
| 载体初判 | 🟡 **分层体**：事件捕获与生命周期感知 = 🟢 页内可达（机制早已存在）；「推给 AI」的**通道 = 🟢 页内可建但为架构级新形态**（P1，非单工具）；跨导航持久续接 = 🔴 需宿主/扩展（session 语义）→ 依赖 O-002 裁决 |

#### C-02 多标签/窗口管理

| 维度 | 内容 |
|------|------|
| 用户真实场景与痛点 | ①AI 想在**新标签页**打开参考链接、查证后回来——现在做不到（window.open 跨域页面 AI 无控制，且触发即离开 AI 运行上下文）；②AI 需要**枚举当前已打开标签**（「找到那个写着发票的标签」）——人类 tab 浏览的基础操作，AI 完全不可表达；③多标签对比/「把结果开在另一个窗口」等人类日常，AI 全部不可表达。痛的本质：**AI 被锁死在「当前这一页」，浏览器的多标签/多窗口维度对 AI 是黑盒** |
| 候选用户故事 | 作为 AI 操作者，我希望能打开/切换/关闭标签与窗口，以便像人类一样在多页面间查证与对比；作为 AI 操作者，我希望能枚举当前打开的标签（标题/URL）以定位「用户正在看的那一页」 |
| 现有状态 | v3 已裁决 out（NG-003/NG-009，归 F-14 扩展宿主）；无任何工具 |
| 浏览器可达性事实 | **网页内不可达**：无枚举/激活/关闭 API。window.open 仅能新建（受弹窗拦截，需用户手势上下文）且对**跨域**新页无控制；同源新窗可用 opener 引用 + postMessage 有限通信。`chrome.tabs` / `chrome.windows` = **扩展专属 API**（需 tabs/windows 权限） |
| 载体初判 | 🔴 **需浏览器扩展**（chrome.tabs/chrome.windows 语义）；页内 window.open 子集（🟢）价值低且破坏 AI 会话上下文（v3 FR-027 已记录导航破坏语义）→ 归属扩展线，O-006 解冻候选 |

#### C-03 对话框处理（alert/confirm/prompt）

| 维度 | 内容 |
|------|------|
| 用户真实场景与痛点 | ①无人值守自动化中页面弹 `confirm('确定删除？')` 或 `alert` —— **模态框阻塞主线程**，AI 既看不到也不知道，流程卡死直到用户手动点掉（v3 打印对话框「用户侧确认」正是同一痛点的先例）；②AI 想**替用户点掉**这些框（接受/拒绝）——无工具；③prompt 对话框需要输入，AI 无法代答。痛的本质：**JS 模态框是页面内最常用的「同步询问原语」，AI 操作浏览器却无法应答** |
| 候选用户故事 | 作为 AI 操作者，我需要接管/应答页面弹出的 alert/confirm/prompt，以便无人值守流程不被模态框卡死；作为被 AI 辅助的用户，我不希望每个删除确认框都要我亲手点 |
| 现有状态 | 无工具；打印对话框「用户侧确认」先例（FR-026）；授权失败转译基建存在（FR-009/EC-003） |
| 浏览器可达性事实 | **override window.alert/confirm/prompt（同 realm 早期 hook）页内可达**——对页面自身 JS 调用生效；各 iframe 有各自 window 需分别 hook（同源可达，跨域 iframe 不可）。`beforeunload` 页内可控。**浏览器原生对话框**（HTTP 认证弹窗、权限 prompt、下载/打印原生确认）页内**不可** hook → 需扩展/CDP。非可信 override 对 isTrusted 无要求（对话框无此概念），可行性高 |
| 载体初判 | 🟡 **分层体**：页面 JS 模态框 = 🟢 页内可达（override hook，主场景）；浏览器原生对话框 = 🔴 需扩展/CDP（边界项）→ O-008 安全门禁关注（override 的「自动点掉」有误确认风险） |

#### C-04 网络层观察/拦截（DevTools Network 等效）

| 维度 | 内容 |
|------|------|
| 用户真实场景与痛点 | ①AI 排障：宿主页某个接口 500/超时/缺 header，用户问「为什么失败了」——AI **看不到页面发出的请求**（web-fetch 只是 AI 自己发请求），只能猜；②AI 想**观察请求序列**（「这个表单提交带了哪些字段」）——不可表达；③AI 想**在请求发出前修改**（改 header/URL/响应）做调试/测试——不可表达。痛的本质：**A2（F12 等效）公理在网络面板场景落空——F12 的 Network 面板是开发者查问题第一工具，AI 无等价物** |
| 候选用户故事 | 作为 AI 操作者，我需要查看宿主页发出的请求（URL/状态/响应头）以便诊断接口失败；作为 AI 操作者，我需要能拦截并修改请求/响应以便测试边界情况 |
| 现有状态 | 无工具；全仓无 Network 观察/拦截痕迹；web-fetch/web-search 走 PlatformEnv.fetch（AI 主动侧） |
| 浏览器可达性事实 | **页内可达面（受限）**：PerformanceObserver（resource timing：URL/耗时/大小，无状态码，受 TAO/CORS 限）；**fetch/XHR monkey-patch**（同 realm，可观察 URL/状态/响应头、可 clone 读响应体、可在请求发出前改参数）——对「宿主页自身网络」可达（lgdl-web 同源宿主 = patch 自己的宿主页）；service worker 拦截（需宿主已注册 SW，lgdl-web 现无）。**不可达面**：非 JS 发起的子资源（img/script/css/导航）、iframe/worker 各 realm、先于网络栈的拦截（响应体修改缓存等）= 需扩展 webRequest（MV2）/declarativeNetRequest（MV3）/CDP Network 域 |
| 载体初判 | 🟡 **分层体**：宿主页自身 fetch/XHR 面观察+拦截 = 🟢 页内可达（instrumentation）；DevTools 全局面（全部子资源/跨 realm/先网络栈） = 🔴 需扩展/CDP → O-003 载体归属裁决 + O-008 门禁（拦截修改属高风险写面） |

#### C-05 文件上传（input[type=file]）

| 维度 | 内容 |
|------|------|
| 用户真实场景与痛点 | ①AI 帮用户填表到最后一步「选择文件上传」——**v3 显式报不可用**（NG-004），流程断在最后一环；②AI 侧已有文件内容（如导出的 CSV、生成的图片）想塞进 file input 上传——不可表达；③用户磁盘文件的路径/选择只能用户手工做，AI 无法代劳。痛的本质：**「表单完整生命周期」（填→传→交）断在上传一环**，而上传是人类表单场景高频件 |
| 候选用户故事 | 作为 AI 操作者，我需要能把「我已有内容/用户授权选择的文件」填入文件上传框，以便完整走完表单流程 |
| 现有状态 | NG-004 显式不可用（platform-dom.ts:1462/1805/1850；dom-tools.ts:685；spec.md:108） |
| 浏览器可达性事实 | 浏览器安全模型禁止程序化赋「真实磁盘路径」（无路径概念，需用户手势）。**受限页内路径存在**：①DataTransfer + 内存 File/Blob 构造 → `input.files` 注入（**内容已在 AI 侧**时可达；对 React 受控/change 事件行为需最小验证）；②File System Access `showOpenFilePicker`（用户手势选择拿 File 句柄，再经 ① 注入或直传）——**磁盘文件须用户一次点击授权**；③真实路径直接注入 = CDP `DOM.setFileInputFiles`（需扩展 debugger/CDP 面） |
| 载体初判 | 🟠 **待定**：内存文件 DataTransfer 注入 🟢（可达性高，需验证 + **解冻 NG-004 须作者裁决**，O-006）；磁盘文件 = 🟢（FSA 用户手势授权，受限）+ 🔴 真路径注入（CDP）→ v3「显式不可用」行为变更属破坏性语义，O-006 必裁 |

#### C-06 cookie 读写/删除

| 维度 | 内容 |
|------|------|
| 用户真实场景与痛点 | ①AI 想判断宿主页登录态——关键 session cookie 常为 **HttpOnly，页面读不到**；②AI 想为测试/调试设置 cookie（如切换租户/AB 实验）——无工具；③用户问「这个站点给我种了哪些 cookie」——不可表达。痛的本质：**会话/身份状态是浏览器操作的核心上下文，AI 对它零感知零控制**；且 cookie 属敏感凭据面，v3 敏感字段策略（FR-024）未覆盖 |
| 候选用户故事 | 作为 AI 操作者，我需要读取/设置/删除 cookie，以便判断登录态与准备测试环境（受凭据护栏约束） |
| 现有状态 | 无工具；全仓 grep cookie = 0 命中；敏感字段脱敏策略存在（FR-024）但未含 cookie |
| 浏览器可达性事实 | **页内可达面**：`document.cookie` 读写同源 cookie（**非 HttpOnly**；Secure cookie 可经 JS 写但仅 HTTPS；HttpOnly 不可读/写）。**不可达面**：HttpOnly cookie、跨域站点 cookie、按域/过期时间批量管理 = `chrome.cookies` API（**扩展专属**，需 cookies + host 权限）。页内 document.cookie 写 = 高风险凭据面（O-008 门禁必挂） |
| 载体初判 | 🟡 **分层体**：非 HttpOnly 同源 cookie = 🟢 页内可达（写面须门禁）；HttpOnly/跨域/域级管理 = 🔴 需扩展 → O-008 凭据护栏必裁 |

#### C-07 剪贴板富内容/文件粘贴

| 维度 | 内容 |
|------|------|
| 用户真实场景与痛点 | ①AI 想把页面表格以**富文本/HTML** 复制走（保留格式）或把**图片**复制——v3 clipboard 仅文本（clipboard.ts 文本面已接线）；②AI 需要读用户粘贴的**富内容**（HTML/图片/文件）——不可达；③「复制这段富文本到文档里」的人类高频操作，AI 只能给纯文本。痛的本质：**v3 剪贴板只覆盖 text/plain 一个 MIME 面，富内容生态（text/html/image 文件）整体缺环** |
| 候选用户故事 | 作为 AI 操作者，我需要读写富文本/图片剪贴板内容，以便完整承接「复制粘贴」这一人类最高频操作 |
| 现有状态 | clipboard 文本读写已建已接线（platform.ts:626-637；v3 接线）；富内容无 |
| 浏览器可达性事实 | **页内可达面**：`navigator.clipboard.write` 可写 ClipboardItem（text/html、image/png 等 Blob 类型），**读非文本受限**（安全上下文 + 权限 + 用户手势）；`paste` 事件可读 clipboardData（用户主动粘贴时含 text/html/files）。**不可达面**：无用户手势读系统剪贴板/跨会话剪贴板历史（扩展亦受手势限制，仅 contextMenus/commands 通道可豁免部分） |
| 载体初判 | 🟢 **网页内可达**（富内容 write + paste 事件读；受安全上下文/手势约束，授权转译 FR-009 沿）→ v3 文本面扩展，无扩展线依赖（系统级豁免需求才需扩展） |

#### C-08 touch 手势（tap/swipe/pinch）

| 维度 | 内容 |
|------|------|
| 用户真实场景与痛点 | ①宿主应用若面向触屏/平板（PWA/移动形态）或页面含触摸交互（轮播 swipe、地图 pinch、触控列表），v3 交互全谱（mouse/pointer 合成）**无法表达触摸手势**；②AI 想在移动端形态调试触摸行为——不可达。痛的本质：**v3 交互全谱以桌面 pointer 为纲，触屏生态位（人类的拇指/触摸操作）未覆盖** |
| 候选用户故事 | 作为 AI 操作者，我需要派发触摸手势（点按/滑动/双指缩放），以便在触屏形态页面上操作 |
| 现有状态 | v3 交互 13 子命令 = click/hover/scroll/zoom/dblclick/contextmenu/long-press/drag/focus/blur/type/press（pointer/mouse 面）；touch 无；NG-007 合成事件局限公开 |
| 浏览器可达性事实 | **页内可达面（受限）**：TouchEvent 可构造并 dispatch（同 click/type 的合成事件局限，isTrusted=false，NG-007 同族；桌面 Chrome 对合成 touch 的支持/手势识别可用性需最小验证）。**不可达面**：真受信触控（isTrusted=true，多指手势/惯性语义）= CDP `Input.dispatchTouchEvent`（需 debugger/CDP 面） |
| 载体初判 | 🟡 **分层体**：合成 touch = 🟢 页内可达（与 v3 click/type 同局限同处理，NG-007 延续）；真受信触控 = 🔴 需扩展/CDP → 移动端价值假设待验证（O-003 范围 + Q-013） |

#### C-09 Shadow DOM / iframe 穿透定位

| 维度 | 内容 |
|------|------|
| 用户真实场景与痛点 | ①宿主页若用 Web Components/影子 DOM（lgdl-web 或未来消费端），**CSS 选择器无法穿透 shadow 边界**——AI 看得到组件但定位不到内部元素；②宿主页内嵌 iframe（同源子应用/不同源第三方），querySelector 不进入 iframe 文档——AI 对「页中页」内容不可定位。痛的本质：**v3 定位语法以 CSS 基线（v3 裁决），而现代页面结构（shadow/iframe）天然超出单文档 CSS 语义**——「看到的元素」与「能定位的元素」之间存在结构断层 |
| 候选用户故事 | 作为 AI 操作者，我需要能定位到 Shadow DOM 内部与 iframe 文档中的元素，以便操作「看到却选不中」的内容 |
| 现有状态 | v3 定位 = CSS selector 基线（locator.ts）；无 shadow/iframe 穿透逻辑；跨域 iframe = F-14 隐含边界（NG-002） |
| 浏览器可达性事实 | **页内可达面**：open Shadow DOM 可手动穿透（element.shadowRoot.querySelector 递归走查）；同源 iframe 可经 contentDocument 进入（跨文档查询可达）。**不可达面**：closed Shadow DOM（shadowRoot 为 null，不可穿透）；跨域 iframe contentDocument 抛 SecurityError（SOP）→ 需扩展 content script（all_frames 注入）或 CDP DOM 域全树 |
| 载体初判 | 🟡 **分层体**：open shadow + 同源 iframe = 🟢 页内可达（定位语法/走查逻辑增强面）；closed shadow + 跨域 iframe = 🔴 需扩展/CDP（与 F-14 跨域同族，NG-002 防抢跑）→ O-003 归属裁决 |

#### C-10 下载管理（下载进度/完成回调）

| 维度 | 内容 |
|------|------|
| 用户真实场景与痛点 | ①AI 触发下载（v3 save download 链/截图自动下载）后，**不知道下载是否完成/失败/多大**——「点了下载」与「下载完成」之间是黑盒；②AI 想枚举下载历史/取消进行中的大下载/打开下载文件夹——不可达；③用户问「刚才那个文件下到哪了」——AI 无法回答。痛的本质：**v3 有「触发下载」没有「下载生命周期」——人类能看到浏览器下载栏，AI 看不到** |
| 候选用户故事 | 作为 AI 操作者，我需要知道 AI 触发的下载何时完成/失败及其大小，以便确认产物落盘并继续后续步骤 |
| 现有状态 | save/download 触发链已建（save-file.ts:83-93，FSA showSaveFilePicker + a[download] 两路径）；无完成/进度回调（页面侧不可感知下载管理器状态）；下载历史管理 = v3 NG-003 out（扩展专属） |
| 浏览器可达性事实 | **页内可达面（替代路径）**：若走 FSA `showSaveFilePicker` 流式自写（自己 open writable 流写入），可感知完成/进度——**但改变了「浏览器下载」语义为「应用内保存」**，且需用户手势授权。**不可达面**：真实「浏览器下载管理器」语义（枚举/进度/取消/历史/打开文件夹）= `chrome.downloads` API（**扩展专属**）。页面 a[download] 触发后无完成事件（iframe onload 等 workaround 不可靠） |
| 载体初判 | 🔴 **需浏览器扩展**（chrome.downloads 语义）为真下载管理；🟢 FSA 自写路径为「可感知完成」的替代面 → 语义取舍（真下载 vs 应用保存）O-003/O-006 必裁 |

#### C-11 权限模拟（geolocation/camera/mic 授权模拟）

| 维度 | 内容 |
|------|------|
| 用户真实场景与痛点 | ①AI 自动化测试宿主页的定位功能——每次都要手动处理权限 prompt 或真实定位；②AI 想模拟「用户拒绝授权」分支做测试——不可达；③宿主页调 getUserMedia 而环境无摄像头——AI 无法让流程继续。痛的本质：**v3 只有「授权失败转译」（FR-009：把浏览器拒绝翻译成可读错误），没有「授权态模拟」——测试/演示场景的权限分支不可自动化** |
| 候选用户故事 | 作为 AI 操作者，我需要模拟浏览器的授权结果（允许/拒绝/假定位/假媒体流），以便自动化测试权限相关流程 |
| 现有状态 | 授权失败分类转译已建（classifyCapabilityError/translateCapabilityError，FR-009/EC-003）；无授权态模拟 |
| 浏览器可达性事实 | **页内可达面 = 「假 API 注入」而非「授权模拟」**：patch navigator.geolocation/getUserMedia 可在页面脚本层返回假定位/空 MediaStream——这是**欺骗页面**而非改变浏览器授权态，页面自身权限状态（permissions.query）不变；且属高风险注入面。**真授权态模拟**（让权限 prompt 自动放行/拒绝、返回系统级假定位）= CDP `Browser.setPermission` / `Emulation.setGeolocationOverride`（需 debugger/CDP 面）或浏览器启动 flag（chromium 冒烟可用的--use-fake-ui-for-media-stream 类） |
| 载体初判 | 🟠 **待定**：真授权模拟 = 🔴 需扩展/CDP/启动 flag（测试侧）；页内 patch「假 API」= 🟢 可达但性质是欺骗注入（风险面，O-008 裁是否允许）→ 价值/风险比待作者裁 |

> 汇总计数（§3.3）：🟢 纯页内可达 1 项（C-07）｜🔴 纯需扩展 2 项（C-02/C-10）｜🟡 分层体 6 项（C-01/C-03/C-04/C-06/C-08/C-09）｜🟠 待定 2 项（C-05 上传/C-11 权限模拟）。**「分层体」占多数 = 载体分层不是二值判断，而是同一能力内按语义切面归属不同实现面**——这是 v4 分界工作的核心复杂度。

### 4.2 分层判断依据摘要

1. **判据 = 浏览器安全模型 + API 归属**（知识面事实，非方案偏好）：
   - 「页内可达」判据：目标对象位于**宿主页同 realm 可及范围**（同源 DOM/自身网络/自身模态框/同源 cookie/剪贴板文本与富内容写/合成事件派发），且浏览器 Web 标准提供了入口（addEventListener/patch/override/document.cookie/clipboard/DataTransfer/TouchEvent）。
   - 「需扩展」判据：目标对象位于**浏览器外壳/跨 realm/先网络栈/系统级**（tab/窗口/下载管理器/HttpOnly 与跨域 cookie/非 JS 子资源/closed shadow/跨域 iframe/原生对话框/真受信输入/真授权态），浏览器仅向扩展（chrome.* API）或 CDP/debugger 暴露。
   - 分层体的普遍性说明：现代浏览器的能力边界**不在「能力」而在「对象归属」**——同一能力（网络观察/文件上传/定位）在「宿主自身对象」上页内可达、在「浏览器/系统级对象」上必须扩展。故 v4 载体分层应按**切面（aspect）**而非**能力（capability）**划分。
2. **v3 已判 out 项（C-02/C-10 及 C-05 的 NG-004）在 v4 的语义 = 「解冻候选」**：v3 的记录是「当前载体（网页内）不可承载」，v4 引入扩展载体后「不可承载」前提变化 → out → in 的边界变更须作者显式裁决（O-006），并伴行为变更（显式不可用 → 可用）的发布说明。
3. **分层不预设实现**：🟢 切面 = 机制上当前架构即可表达（是否做、以何工具形态做 = spec/plan 与作者裁决）；🔴 切面 = 依赖扩展载体（扩展是否引入 = O-004/O-005）；🟠 待定 = 需先最小验证（浏览器行为）再定归属。

### 4.3 载体分层对 AI 契约的含义（问题域表述，非设计）

- **透明性未定**：当同一能力（如 C-04 网络观察）页内切面与扩展切面能力深度不同时，AI 视角是「无差别调用、载体差异透明」还是「能力归属显式告知、缺失面可读降级」（v3 各工具的「不支持 + 归属说明」先例）——未定义，需作者裁（O-003）。
- **新增能力与既有契约的关系 = additive 候选**：按 v3 NG-008/FR-001 纪律，11 项落地形态（无论载体）应为 ToolEntry 追加/新工具/新子命令/PlatformDomOps 或新缝 additive 扩展；**例外** = 解冻 NG-003/NG-004 属「从显式 out/不可用到可用」的语义变更，非纯 additive（O-006）。
- **安全门禁必须随能力面升级**：cookie（凭据面）、网络拦截（写面）、对话框 override（自动确认面）、权限模拟（欺骗面）、富剪贴板（敏感内容面）——全部触及 v3 敏感字段/risk/untrusted 模型未覆盖的新对象类型（O-008）。

## 5. 浏览器扩展架构线：线索与开放问题

> 本节只梳理「扩展作为新架构线」的**问题与线索**（作者 v4 指令指定梳理维度），不做方案设计（plan 职责）。

### 5.1 为什么 11 项把 v4 逼到「扩展」问题面前（事实链）

- C-02/C-10 及 C-04/C-06 的深层面、C-09 的跨域面、C-11 的真授权面 = `chrome.tabs/windows/downloads/cookies/webRequest/declarativeNetRequest`、content script（all_frames）、CDP/debugger——**全部是浏览器扩展（或 debugger）专属 API**，网页内物理不可达（§3.3 可达性事实）。
- v3 已三处把同类能力判 out 归「F-14 扩展宿主」（NG-003/NG-009/FR-028 整页截图），但 **F-14 是 v1.1 线产品（任意站点 web-cli 消费端，门槛式未启动）**——v3 的 out 实际上是「挂账给一个不存在的载体」。
- v4 作者指令 = 这些能力仍全部纳入梳理 → **问题域需要一个「浏览器外壳能力载体」的答案**：引入扩展（新工程领域）vs 继续挂账 F-14 vs 页内替代面兜底——三选未定（O-004/O-005）。

### 5.2 扩展线的形态线索（仅问题化，非方案）

| 线索 | 问题化描述 | 开放点 |
|------|-----------|--------|

| 安全评审面 | MV3 权限最小化、untrusted 门禁跨载体延续、审计面覆盖扩展调用、凭据面（cookie/上传/剪贴板富内容）护栏 | O-008/O-010 |

### 5.3 开放问题汇总（扩展线专章，作者裁决输入）

- 扩展线**是否在 v4 引入**（新工程领域、与 v0.8/v0.9 版本位叠加风险），还是 v4 仅做「分界 + 预留契约」、扩展实现留给 F-14 线（O-004/O-005）？
- 若引入：与 F-14 的边界（浏览器外壳机制层 vs 任意站点 web-cli 产品线）与门禁关系（O-005）？
- 载体分层后的「页内快赢面」是否先行（与扩展长线解耦排波次）（O-001/O-003）？

### 6.4 边界界定初步映射（spec 输入；非方案）

**→ 页内可达面（🟢，机制上当前架构可承载，作者裁 in/out 后进 spec）**

**→ 需扩展面（🔴，依赖扩展载体，O-004/O-005 裁决后进扩展线）**

**→ 待定（🟠，先最小验证再定归属）**
- C-05 上传（DataTransfer 兼容验证 + NG-004 解冻）；C-11 权限模拟（假 API 注入 vs 真模拟的价值/风险）。

- OS 生态位（os-cli-base，NG-001）；LGDL 业务语义（NG-006）；worker 沙箱语义不混入（NG-010）。

## 7. 竞品参考（事实记录，载体与事件流视角，不做方案评价）

| 竞品/参照 | 是否处理过类似问题 | 处理方式（事实） | 与我们场景的差异 |
|----------|-------------------|----------------|----------------|
| Playwright / Puppeteer（浏览器自动化事实基线，知识面） | 是（事件流与多页面覆盖最完整） | **事件模型**：page.on('console'/'request'/'response'/'dialog'/'framenavigated'/'download'/'worker') + page.waitForEvent——**推式事件订阅是 Playwright 架构一等公民**；多页：browser.contexts()/pages()/newPage()；对话框：page.on('dialog') → accept/dismiss；上传：setInputFiles（CDP 侧真路径注入）；网络：page.route() 拦截/改请求响应；权限：context.grantPermissions/geolocation override；下载：page.on('download') + 完成回调 | 独立进程驱动浏览器（CDP 协议），非「宿主页内嵌工具集」；其**事件订阅模型与多页/对话框/下载/网络拦截原语清单**是 v4「事件流 + 外壳能力」的事实参照；安全模型（无 PRM/untrusted）与我们完全不同，不可照搬 |
| Chrome DevTools Protocol（CDP） | 是（浏览器级能力的事实标准） | Network/Tabs/Page/DOM/Input/Browser.setPermission/Emulation.setGeolocationOverride/DOM.setFileInputFiles/Page.captureScreenshot/Page.setDownloadBehavior——浏览器外壳与系统级能力经 debugger 域暴露 | 扩展 chrome.debugger 或独立驱动可达；**「网页内不可达的浏览器级能力大多在 CDP 有对应域」是 §3.3 可达性判据的事实来源**；v3 截图/整页 out 已标注 CDP 归属 |
| 浏览器扩展 API 生态（chrome.tabs/windows/downloads/cookies/webRequest/declarativeNetRequest，MV3） | 是（外壳能力的唯一页面外标准面） | chrome.tabs/windows（枚举/激活/新建/关闭）、chrome.downloads（枚举/进度/取消/历史）、chrome.cookies（HttpOnly/跨域）、MV3 declarativeNetRequest（声明式网络规则） | 浏览器官方扩展面 = §4 分层表「🔴 需扩展」列的 API 事实来源；F-14（ROADMAP v1.1）将基于此生态，但其协议发现/消费端定位与 v4 机制层不同 |
| Computer-use / browser-use 视觉路线（知识面） | 部分（对话式事件感知） | 截图 → 模型看 → 坐标操作；对模态框/事件靠视觉发现 | 无结构化 DOM 事件订阅/外壳管理精确性；记录事实，不做方案推荐 |
| 仓库先例：v2/v3（F-25/同批） | 部分（拉式全谱完成，推式/外壳未做） | v2 九域 + v3 DOM 27 子命令全为 request→response；wait 用 MutationObserver 拉式；书签/标签/下载/整页截图判 out 归 F-14 | v2/v3 = v4 的机制底座与边界基线（§3.1/§3.2）；11 项中 7 项已有 v3 out/受限记录 → v4 解冻候选 |

> 注：以上只记录事实与差异，不推导「我们应该怎么做」。Playwright/CDP/扩展 API 均「知识面」标注——v3 起即以此类事实基线支撑可达性判据，非本仓调研文档覆盖对象（本仓调研 = docs/research/agent-capabilities 9 框架，其浏览器 DOM/外壳面为零）。
