## 2. 上下文与边界

### 2.1 上下文

父规范 §2.2 的**未配置路径偏颇 + 异常兜底缺位 + 门禁/体积治理面**全部落在本叶：F-36 让 `free-input` provider `when` **恒真**（`providers.ts:205-221,217`）⇒ 未配置也显示「自由输入…」终端，但作者口径②逐字「自由输入在没有 LLM 的场景下，**是不可行的**，只能给**确定性操作**」（未配置提交走零 token `variant:'llm-unconfigured'` 返场，`service-worker.ts:945-956`）；F-36 **无** LLM 异常兜底（`onFinish` 只校验装配 `:1027-1043`；LLM 连续失败 ⇒ `finish('llm-failed')`，面板只 `maybeRecommend('idle')` `sidepanel.ts:4140-4152`；**无「配置新 LLM」推荐**）。

**关键事实**：未配置确定性引导**底座已有**（`llm.unconfigured` risk → `OPS_RECOVERY_ROWS` → `op.llm-config` chip，`sidepanel.ts:4167-4194`；`providers.ts:52-61`），**只是被恒真终端稀释**；「配置新 LLM」也有 op 可落（`op.llm-config`，`confirm` 档，`op-table.ts:120`）。

**本叶的验收锚**：把「未配置 ⇒ 确定性引导且不显示自由输入」与「已配置 ⇒ 终端恒常驻」分相做到**单源判据、零误伤**；把「提醒补一次 → 仍失败 ⇒ 系统兜底」做成**有界、防环、可判**的链；把门禁 / 体积 / 取代台账**逐条等价重锚到终态**且**断言零删除**。
