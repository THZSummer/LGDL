# ADR-V55-011: 体积预算（三叶分列 + 15% 缓冲）+ 跨档位**显式升档**预案

## 状态
ACCEPTED

## 背景

**v5 的教训（逐字登记）**：plan 预算表给 9 op 执行体 3,400 B，**实测仅 `ops.ts` 一项即 3,918 B**，面板接线另 +4,935 B
⇒ **预算低估约 2 倍**，导致 v5-2 R1 **越档位**、必须由编排器裁决**显式升档**（512,000 → 563,200；绝对上限 → 619,520）。
本条 ADR 的存在理由就是**不再重犯**：先给**分列预算 + 上界 + 缓冲**，再排落地（FR-SELF-120 / 124 / R-SELF-006/910 / 纪律第 9 条）。

现行口径（**本轮只读实测**）：

| 项 | 值 | 来源 |
|---|--:|---|
| `dist/sidepanel.js` 现值 | **549,609 B** | `stat` 实测（§1） |
| 生效上限 | **577,089 B** = `min(619,520, floor(549,609 × 1.05))` | 公式 |
| **余量** | **27,480 B**（+5.00%） | 算术 |
| 已登记档位 | **563,200 B** = `ceilTo50KB(549,609)` | `test/size-baseline.ts:3020` |
| 距档位 | **13,591 B** | 算术 |
| 绝对上限 | **619,520 B** = 档位 × 1.10 | `test/size-baseline.ts:3036` |
| 自缚装置 | `SIDEPANEL_CEILING_CAP` = **`record-only`**（不参与判定） | `:418` |
| 授权线 | `authorConfirmation.status` = **`pending-author-line`** | 台账（未闭合义务） |

## 决策

### 1. 分列预算（**基于 v4 / v4.5 / v5 实测增量校准**）

| 叶 | 构成（逐模块） | 预算 | 上界 |
|---|---|--:|--:|
| **v55-1** 驱动者层 | `drivers.ts` **NEW** 2,600 · `terminals.ts` **NEW** 700 · `providers.ts` 900 · `sidepanel.ts` 2,400 · `recommend.ts` 200 · `definition/pipeline/dispatch` 200 | **7,000** | **9,000** |
| **v55-2** 系统流 + 悬置续接 | `suspension.ts` **NEW** 1,300 · `onboarding-flow.ts` **NEW** 1,100 · `llm/status.ts` 120 · `sidepanel.ts` 2,300 | **4,900** | **6,300** |
| **v55-3** AI 编排 + 护栏 + consent + 仲裁 + 收口 | `guard.ts` **NEW** 1,700 · `ai-drive.ts` **NEW** 1,400 · `shared/op-table.ts` 300 · `sidepanel.ts` 2,000 · `settings/panel.ts` 350 · `dispatch/recommend` 150 | **5,900** | **7,600** |
| **Σ** | — | **17,800** | **22,900** |

**校准依据（实测增量，逐轮）**：

| 先例轮 | 实测 | 与本 Feature 对照 |
|---|--:|---|
| v5-1 R1（5 新模块 + 规则迁移 + 集 B 收敛） | **+8,794** | 本叶 v55-1 新模块 **3** 个且更小 ⇒ 7,000 有理 |
| v5-2 R1（5 op + SW 执行器 + 握手 + 掩码卡） | **+11,228** | 本 Feature **零新 op** ⇒ 无此量级项 |
| v5-2 R2（4 op + form + 三表回滚 + settings 收编） | **+17,278** | 本 Feature **零 settings 收编 / 零新卡形** |
| v5-2 review R1（6 模块改动） | **+6,329** | 本 Feature 单叶最大 = v55-3 的 5,900（**低于**该修复轮） |
| v5-3 R2（chip + `data-narrow` + error 出生 + 门禁） | **+4,306** | 本叶 v55-2 = 4,900 同量级 |
| v5-3 review R1（4 项修复） | **+1,188** | 修复轮量级参照 |

**零字节项（本 Feature 的主体工作）**：6 个新门禁 + S0 样本 + node/Chromium 双面判 + 台账 + 人工面清单 + 全部 ADR/plan
⇒ `test/**` 与 `.sddu/**` **不进任何产物**；SW 侧改动（`runChat` 前置判据 / 仲裁队列 / `askBridge` 迟到固化）落 `background.js`
⇒ **不计入 sidepanel 账本**（v5 逐字先例：「落在 **service-worker** 产物（不在本 bundle，故不计入）」）。

### 2. **缓冲校验（硬要求）**

| 情形 | Σ × 1.15 | 判定 |
|---|--:|:--:|
| 预算情形 | 17,800 × 1.15 = **20,470** | ✅ ≤ 27,480（余 **7,010**） |
| **上界情形** | 22,900 × 1.15 = **26,335** | ✅ ≤ 27,480（余 **1,145**） |

⇒ **可行，不触发停机上报**（任务书给出的停机条件 = 「论证不可行」）。

### 3. 累计投影（每叶收口**重登记**后口径）

| 阶段 | 累计 B | vs 档位 563,200 | 生效上限（重登记后） |
|---|--:|:--:|--:|
| 起点 | 549,609 | 未越 | 577,089 |
| v55-1 收口（+7,000） | 556,609 | 未越 ✅ | `floor(556,609×1.05)` = **584,439** |
| v55-2 收口（+4,900） | 561,509 | 未越（余 **1,691**）⚠️ 紧 | `floor(561,509×1.05)` = **589,584** |
| v55-3 收口（+5,900） | **567,409** | **越档位 +4,209** | `min(675,840, floor(567,409×1.05))` = **595,779** |

> 注：每叶收口按既有纪律做**五要素重登记** ⇒ 该叶的**生效上限**随实测基线 `floor(B×1.05)` 前移（这是**已登记的既有机制**，v5 逐轮使用）。§2 的静态校验**故意按未前移的 27,480 B 计**（保守口径）。

### 4. **跨档位的显式升档预案**（EC-SELF-019 / FR-SELF-122 / N-SELF-004）

**预计触发点 = v55-3 收口轮**（累计 567,409 > 563,200，超出 4,209 B）。届时按 V3-VOL-3 走**显式**路径：

| 步 | 动作 | 判据 |
|:-:|---|---|
| ① | 实测 `dist/sidepanel.js` 终值 `B_final`（`stat -c %s`） | 登记值 == 实测产物 |
| ② | 档位显式升档：`ceilTo50KB(B_final)` = `ceil(567,409/51,200)×51,200` = **614,400** | `test/size-ruling-vol3.test.ts` ≥12 全绿 |
| ③ | 绝对上限同源前移：`614,400 × 1.10` = **675,840** | 三值同源 |
| ④ | `newBaselineBytes` = `B_final`（同源前移）；`SIDEPANEL_BASELINE_BYTES_TIMELINE` **只追加** | 历史保留（不改写） |
| ⑤ | 五要素重登记（前后值 / 日期 / 来源 / 理由 / 历史保留 + 构建命令 + **逐模块 metafile 归因**，ΣΔ + glue == 登记增量） | `size-budget` / `size-growth-evidence` 全绿 |
| ⑥ | `authorConfirmation.status` **保持 `pending-author-line`**（占位规则）；文书**不得**出现「档位已确认」类表述 | 枚举值合法 + `size-ruling-vol3` 断言 |
| ⑦ | 若**未**越档位（实测 < 563,200）：**如实登记「本 Feature 未跨档位」**，不制造升档条目 | 二态显式 |

**明确禁止**：静默放宽上限 / 静默改档位 / 引入新自缚 cap（NG-SELF-009）/ 以删除断言换体积（NG-SELF-008）。

### 5. 减体积优先级（越预算时**按序**执行；**不触碰**断言 / 容差 / 档位口径）

1. **下移 SW**：把纯记账（护栏计数 / 活跃度 / 队列）移到 `background.js`（不计账）；
2. **元组化声明数据**（v5 `ops.ts#IMPL` 先例：命名对象字面量每字段 ≈10 B 格式开销）；
3. **复用既有文案**（系统行 / receipt），零新字符串；
4. **合并驱动者声明行**（同 `when` 者共用一行）；
5. **显式登记未落地项**（护栏某控制 / 某驱动者延后）为未闭合义务 —— **绝不以删判据 / 放宽容差 / 静默降档实现**。

### 6. 每叶的**体积证据义务**（收口门禁清单的一部分）

| 义务 | 判据 |
|---|---|
| 五要素重登记（每叶增量） | `test/size-budget` + `size-growth-evidence` 全绿 |
| 逐模块归因 | `dist/build-meta.json` 的 `bytesInOutput`；Σ 逐模块 Δ + 未归因胶水 **==** 登记增量 |
| 披露算术机核 | `validateReRegistrationDisclosure`（既有） |
| cap 纪律 | `SIDEPANEL_CEILING_CAP === 'record-only'` 且判定不含 cap；`SIDEPANEL_CEILING === SIDEPANEL_CEILING_UNCAPPED` |
| 红线零容差 | `content.js` 177,076 / `pick-layer.js` 34,358 **逐字节** + sha 双命中 |

## 后果

**正面**
- 体积从「事后惊喜」变为**事先有界**：预算 + 上界 + 缓冲三层，且**上界情形也通过**（余 1,145 B）。
- 跨档位**预登记**而非事后补救：`pending-author-line` 的占位语义被保住（不得伪称确认）。
- 明确区分「计账产物」（`sidepanel.js`）与「不计账产物」（`background.js` / `options.js` / `test/**`）⇒ 主动性的**账本复杂度**天然落在 SW 侧。

**负面 / 代价**
- v55-2 收口距档位仅 **1,691 B**（预算情形）⇒ 若该叶出现 review 修复轮（历史均值 +1,188 ～ +6,329 B），**跨档位会提前到 v55-2**。这不是「不可行」，而是**触发点前移**：预案（§4）对**任一叶**成立（谁先越谁登记）。登记为风险 R-V55-110 的邻域。
- 分列预算仍可能低估（v5 教训）⇒ 用**上界列 + 减体积优先级**兜底；若上界也被突破（Σ×1.15 > 27,480），则**停机上报**（走任务书给定的 V3-VOL-3 档位流程），**不静默**。
