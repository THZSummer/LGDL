## 2. 上下文与边界

### 2.1 上下文

- **R5**：`runChat`（`background/service-worker.ts:878-941`）**无任何配置门禁**——`chatBusy` 检查后直接 `s.keys.load()`（`:893`）→ `providerById` → `providerChat`；未配置时**表现为 LLM 错误事件**（`:920-921` `onLLMError` → `llmErrorEvent`）→ 落 idle 推荐。**被动撞墙式**。
- **B3**：`llm.unconfigured` 阻塞事实**只在 `op.llm-config` 分支被动写入**（`sidepanel.ts:1290-1302` 的 `noteLlmBlockedFact`；注释逐字：「their fact is an **observed block event**（the repairing op failed / was refused），not a static preference」）。
- **B5**：`onboarding` provider **仅首装**（`firstRun && pendingSteps.length > 0`，`providers.ts:125-134`），且 `pendingSteps` 恒为 `['授权当前站点']`（`sidepanel.ts:1835-1836` / `:1094`）；`maybeRecommendFirstRunEntry()`（`:1895-1909`）**每次面板生命至多消费一次**。
- **A1/B4**：`BLOCKED_TERMINALS` 恰 5，其中 `llm.unconfigured` 的修复 next **就是 op 自身**（`OPS_RECOVERY_ROWS`，`providers.ts:57-58`；`BLOCKED_RECOVERY_TRIGGER` 对应值为 `null` = op-driven，按终态键控对象）。
- **A3（S2 先例）**：「阻塞解除 → **自动恢复**」已被 v5 机器化（`test/s2-deadend-chain.test.ts` + `test/ui/fixtures/s2-chain.mjs` + `test/ui/no-dead-end.mjs`）。

⇒ **「已装未配」是当前零覆盖的核心场景**（首装 ≠ 已装未配）；且**「配置」这件事的终点缺失**：用户为了某件事去配 LLM，配完之后**那件事不会自己继续**。

### 2.2 范围（做 / 不做）

**做（in）**：

- **`runChat` 前置配置判据**（主动式）：在**发起 provider 调用之前**做**确定性**判据；未配置 ⇒ **主动产出确定性引导**（**不**先撞 provider 再以错误事件收场）。
- **`llm.unconfigured` 触发语义升级**：从「被观测」→「被识别」（**双源并存**；被动路径保留）；既有 op 恢复链（`OPS_RECOVERY_ROWS` / `BLOCKED_RECOVERY_TRIGGER`，按终态键控）**逐条保留、零改写**。
- **多步确定性引导流**：步骤集合单源 + 顺序确定 + 每步可判（**至少**：识别 → 引导 → 采集 → 完成）；**零 LLM 调用**、同输入同路径。
- **配置完成 → 自动续接悬置任务**：**悬置任务单源登记**（谁在等 / 等什么 / 依据什么事实）；配置成功回执后**自动**把悬置任务接上；**不要求用户重新输入**。
- **两场景覆盖**：**首装**（既有 `R-ONBOARDING` **保留不取代**）+ **已装未配**（**不得依赖 `firstRun`**）。
- **取消 / 放弃非死端 + 不重复打扰**（同因不重复 + 三纪律：事件化 / 至多一次 / 事实到位）。
- **不跳走**：引导全程**流内闭环**（零视图切换 / 零 `#open-settings` 调用）。
- **掩码卡复用**：配置采集恒经 `op.llm-config`；法八四面零明文**不退化**（`law8` 25 断言不减）。
- **配置探测判据**（确定性可判、无 LLM 调用）——主题① ↔ 主题② 的**唯一分流依据**。
- **承载 S0 分支 B 的必判项**（未配置 ⇒ 系统流驱动配置 ⇒ 配置完成自动续接）。

**不做（out）**：

- **不做主题② 的 AI 主动性与护栏**（经 `op.turn` 主动发回合 / 三档清分 / 打扰·成本·防环）——那是 `v55-3`。
- **不新造配置面**：不新增第二套配置引导 / 第二套凭据写入路径 / 新的配置 op；设置视图保留为**管理面**（法六不变）。
- **不新增静态权限**（**连 `optional_permissions` 也不新增**）；不改 `manifest.json`；不改 `KIND_SET`；不改 12 kind / 零宿主。
- **不碰 `src/content/**` / `dist/content.js` / `dist/pick-layer.js`**；**不动判定链**（`zeroDiffFiles` 9 项）；不改 ROADMAP；不碰 `design/**`；不改写 v5 产物。
- **不做凭据存储侧加密 / 生命周期**（v5 `PO-ALLN-003` 延续：只保证**流内零明文**）。
- **不把「引导」实现为跳转设置页 / 打开 options**（违作者「不允许让用户跳来跳去」）。

### 2.3 与父规范的关系

- **权威条文 = 父 `../spec.md`**（§5.5 ONBOARD / §5.9 SUPERSEDE 的 X-SELF-3 / §5.12 S0 的 FR-SELF-131 分支 B / §13 / §14）。本叶只做**范围切片 + 实施口径**，不新增与父冲突的需求；若必须偏离，须先回父规范做显式取代登记。

## 6. 边界情况（本叶相关）

父 `EC-SELF-001~022` 全部适用；本叶执行时**重点验**：

| 父 EC | 本叶执行要点 |
|---|---|
| EC-SELF-009 | **未配置 + 用户取消引导** ⇒ 固化 + 可达 next；**不重复**弹同因引导；后续再「意图需要 LLM」时**可重新**引导（不是永久静默） |
| EC-SELF-010 | **引导中途用户从设置页手动配置完成** ⇒ 识别「已配置」（判据基于**事实**而非动作）⇒ 引导**自动收敛**；悬置任务**仍须**续接（配置来源无关） |
| EC-SELF-011 | **悬置任务在配置完成前已失效**（引用失效 / 站点变更 / 会话切换）⇒ 续接时**重新校验**；失效 ⇒ **不续接** + 固化「原任务已失效」+ 可达 next（**不得**制造假成功） |
| EC-SELF-012 | **配置完成但悬置任务为空** ⇒ **非死端**（产出可达 next）；不得静默结束 |
| EC-SELF-022 | **配置面双套风险** ⇒ 执行体唯一（`op.llm-config`）+ 设置页**同调 op**（零双路径）；反证：第二条凭据写入路径 ⇒ FAIL |
| EC-SELF-004 | 主动识别与被动观测**同时命中** ⇒ 事实**幂等**（不产生两条阻塞事实 / 不弹两条引导） |
| EC-SELF-020 | 保护段被波及 ⇒ **优先保段**；若必须改走八步 |
