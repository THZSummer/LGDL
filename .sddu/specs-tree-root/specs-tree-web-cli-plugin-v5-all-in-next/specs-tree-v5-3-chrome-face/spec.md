## 2. 上下文与边界

### 2.1 上下文

现状下授权态**三处投影、零处常显可点**：工具栏摘要（`view-model.ts:824, 894-902` 的 `已授权` / `未授权` + `band.origin`）、风险位条件性 chip（`l0/risk-rail.ts:29-40`）、首装推荐卡（`recommend.ts:298-305`）——而授权入口**只在首装态**（R1）。作者 ⑧ 反馈逐字：「『未授权 · 零注入』『已授权 · supported』这两项如果属于状态，那就放到最下面的状态栏，上面属于工具、菜单栏，不应该放这两个。」

同时密度口径基于**三档视口**（320 / 400 / 520 + 三档 radio），而 G 稿改为 **280–640 连续宽度 + `data-narrow`（≤360）**；法七的最严口径（✖ 行**行内**带恢复 chip）与 `error ∈ BORN_FROZEN_KINDS` 看似冲突；法八需要一条**可核的零明文判据**而非仅靠净化面。

本叶的工作 = **把状态归位（唯一载体 + 零双写）** + **把宽度做成真实拖拽且口径不动摇** + **把两条新法则落成门禁** + **把共享面收口**。

### 2.2 范围（做 / 不做）

**做（in）**：

- `#auth-state` **状态栏常显两态 chip**（黄「未授权 · 零注入」/ 绿「已授权 · supported」）；状态 ≡ `ctxOf(scene).site.authorized`。
- **授权态唯一载体 + 零双写**：工具栏摘要只留 `origin · 会话`；四词工具栏区零出现；风险 rail 授权类**并入**；状态栏第一行不写授权态；L2 台账指向 chip。
- 黄态点击 → 流内产 `op.authorize` next；绿态点击 → 管理详情（`op.revoke` / `op.rebind` 入口）；两者**不跳走**。
- **可拖动宽度 280–640**（ARIA `separator` 四属性 + 键盘 `←/→` ±10 · `Home`/`End` · 双击复位 400 + clamp + rAF 合并）。
- **`data-narrow`（≤360）** 窄屏兜底；**三档 radio 删除**。
- **密度登记格口径与宽度解耦**（格 = 控件计数；320px 仍为锚点；阈值逐字不动；`#auth-state` 计入默认密度后 6 ≤ 7）。
- **`error` 出生即带恢复区**（阻塞类；append-only 不破）。
- **死端守护门禁**（5 类阻塞逐类 + N = 0 + 死端 = 0 + ✖ 行不裸奔；双向注入反证）。
- **法八四面零明文机核**（流内 payload / digest / 审计 / DOM value + 全部属性）+ **key 直写 key-store** 断言 + 哨兵对抗反证。
- **X5 显式取代**（三档 → 连续宽度；登记格重锚 + 逐格留痕）。
- **父级共享面收口**：体积五要素（本叶增量 + 三叶合计）+ journey 结构重锚（保护段保段或八步取代）+ `design-contract` 共享登记对账 + 取代台账最终一致性。
- 本叶范围的门禁等价重锚（`test:l0` / `test:density` / `test:journey` / `test:stream` / `test:zero-injection` / `density-thresholds`）。

**不做（out）**：

- 不落地注册表 / 管线 / 契约 v2 / 双契约本体（`v5-1`）；不落地 9 op / SW 执行器 / `optional_permissions` / settings 收编 / 断流首验收（`v5-2`）。
- 不改 12 卡类型学（`error` 恢复区是**既有 kind 的铸造扩展**，不是新 kind）；不改三区法则；不新增流内固定宿主（chip / 分隔条**不在流内**）。
- 不碰 `src/content/**` / `dist/content.js` / `dist/pick-layer.js`；不动判定链；不改 `KIND_SET`；不新增安装期静态权限；不改 ROADMAP；不碰 `design/**`（G 稿**零改动**）。
- 不做存储侧加密 / 生命周期（法八只保证**流内零明文**）。

### 2.3 与父规范 / 上游叶的关系

- **权威条文 = 父 `../spec.md`**（§5.2 LAW7 的 012·015 / §5.3 LAW8 的 023·024 / §5.9 CHROME / §5.12 GATE / §5.13 VOL / §5.11 X5 = FR-ALLN-114）。本叶只做范围切片 + 实施口径；偏离须先回父规范登记。
- **接口与 op 实体 = `v5-1` / `v5-2`**：本叶只**消费**（chip 点击产 next / 管理详情挂 op / 死端门禁复用阻塞态枚举单源），不改注册表语义与 op 执行体。

## 8. 交付与执行

### 8.1 上游依赖

**`specs-tree-v5-1-next-registry-pipeline`**（注册表 / 管线 / 双契约 / 阻塞态枚举单源 / act→opId）+ **`specs-tree-v5-2-ops-first-batch`**（`op.authorize` / `op.revoke` / `op.rebind` 落地 + 断流样本 + 掩码卡）必须已完成。本叶只**消费**。

### 8.2 下游consumer

无（末叶）。父级收口 = 本叶收尾报告 + 父 `state.json` 状态登记。

### 8.3 交付物（本叶）

1. `#auth-state` 常显两态 chip + 零双写改造（工具栏 / rail / 状态栏第一行 / L2 台账）。
2. 黄 / 绿 chip 点击行为（产 next / 管理详情）。
3. 分隔条（ARIA + 键盘 + clamp + 双击复位 + rAF）+ `data-narrow` + 三档 radio 删除。
4. 密度登记格口径解耦 + 台账重锚 + 逐格留痕（X5）。
5. `error` 出生带恢复区 + 死端守护门禁（双向反证）。
6. 法八四面零明文机核 + key 直写 key-store 断言 + 哨兵反证。
7. 共享面收口：体积五要素（三叶合计）+ journey 保护段处置 + 双契约 / 取代台账一致性。
8. 本叶范围门禁等价重锚 + 反证留证 + 人工面清单条目。

### 8.4 叶内执行序（供 plan / tasks 参考，**不是需求**）

① 先 **法八四面零明文机核**（判据先立，掩码卡已在 `v5-2`）→ ② 再 **`error` 出生带恢复区**（铸造层，最小侵入）→ ③ 再 **死端守护门禁**（复用 `v5-1` 阻塞态枚举单源 + `v5-2` 断流样本）→ ④ 再 **授权 chip**（两态 + 零双写 + 黄 / 绿点击；**与 rail / 工具栏同步改口径**）→ ⑤ 再 **分隔条 + `data-narrow` + 三档 radio 删除**→ ⑥ 再 **密度登记格口径解耦 + 台账重锚**（X5 等价重锚）→ ⑦ 最后 **共享面收口**（体积五要素三叶合计 / journey 保护段 / 双契约 / 台账一致性）+ 收尾全门禁绿。
