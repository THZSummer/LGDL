## 3. 审查详情（方法与判据）

### 3.1 代码质量
- 只读走查 `src/ui/sidepanel/{disclosure.ts,view-model.ts,l0/*.ts}` 与 `index.html` 的 L0 区段；对每个导出符号做**引用图**（`grep -rn`）判定死代码。
- 空 catch / 吞断言的判据：catch 体是否只含注释或 `return undefined`，且其调用链是否承载断言（`check()`/`assert`）。
- 注释一致性判据：同一规则在**注释、常量、运行时实测**三处是否一致（三方不一致即记为 ⚠️）。

### 3.2 规范符合性
- 逐 FR 从「门禁是否有**直接**断言 → 断言是否覆盖 spec 条文的行为（而非仅存在性）」两级判定；只有常量级单测而无行为断言的条目记 PARTIAL。
- 阈值/口径类以**父 §9 原文**为基准，用「逐字比较」而非「语义相近」判定。

### 3.3 架构一致性
- ADR 判定以「代码是否违反 ADR 的**约束句**」为准，而非以是否实现了 ADR 的建议形式为准。
- 取代台账类：以**真实 `git diff -U0 c2c0e0d..HEAD`** 为唯一事实源，逐 hunk 判定 `modifiedRanges` 覆盖是否有效、`oldTitle` 是否真实存在、protectedRanges 是否用**独立复算**的 sha256/byte 偏移验证。
- 反证类：判定「扰动是否落在门禁读取的**同一路径**」，副本/内联副本/旁路一律降级。

### 3.4 测试质量
- 断言强度三级：① 行为断言（改真值必变）② 存在性断言 ③ 恒真/弱断言（`|| true`、字段非空）。
- 计数纪律：以「同一口径的 before/after」为有效比较；跨口径数字一律标注不可比。
