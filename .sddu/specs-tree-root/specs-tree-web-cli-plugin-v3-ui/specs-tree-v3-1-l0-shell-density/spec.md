## 2. 上下文与边界

### 2.1 上下文

作者两段反馈（「凌乱、没有条理」/「很复杂、很难用，信息密度太高」）的直接对应物是**默认首屏**：现状侧栏同时承载状态 / 会话 / 树入口 / 命令与审计入口 / 站点提示 / 环境守卫 / 确认与问答 / 输入 / 设置 等 5+ 类信息（`src/ui/sidepanel/index.html` = 37,960 B / **54 个 `id`**）。本叶子只做**默认首屏**这一件事，且必须先立「可测基线」，否则后续叶子没有共同判据（discovery 补充 1）。

### 2.2 范围（做 / 不做）

**做（In Scope）**：

1. **L0 常驻骨架**：我在哪（origin + 站点名 + 状态点）· 谁在管我（策略档摘要徽标 + LLM 状态徽标）· 下一步做什么（**当前一张决策卡**：问题 + ≤2 推荐选项 + 「更多选项（还有 N 个）」）+ 「**从页面拾取**」入口 + **一行可点开状态栏**（含 L2 计数摘要）。
2. **五类风险位独立常驻（D3 铁律）**：未授权 / 探测中 / 硬底线被拦 / 破坏性待确认 / 引用失效 —— 独立分区、常驻最上层、**永不折叠**；文字 + 徽标 + 图标三通道；破坏性确认选项不参与折叠。
3. **每回合一道选择题**（末项固定「其他…（我来描述）」+ 兜底输入框用完即收）+ **无常驻输入框**。
4. **收起/展开契约**：一律 `hidden` 属性 + `aria-expanded` / `aria-controls` 成对；展开状态记忆。
5. **可发现性契约**：凡收起必有「摘要/计数 + 文字入口」；禁止无线索隐藏。
6. **密度口径与机器门禁**（本叶子的**核心产出**）：把父 spec §9 的四项口径实现为可复算统计；三段阈值（默认态 ≤7/≤15 · 首装态 ≤9/≤20 · 风险态 ≤17/≤35）× 三档视口（320/400/520）；常驻分区数只登记不上限（C4 反直觉事实）；**6 条反证**（父 §9.3 RP-V3-01~06 中与本叶相关的 01~04）。
7. **首轮真实产物密度基线登记**（对照 A-UI-001）：三档视口实测值 + 日期 + 来源落盘，与设计稿口径数字**分开记录**。

**不做（Out of Scope）**：

- 不做 L1 就地展开的**内容**（后果说明 / 引用证据 / 局部树 / 已决策历史 / 回执证据 / 手势表）→ 归 **v3-2**；本叶只提供「折叠器契约 + 摘要/计数契约」。
- 不做 L2 四类视图的**内容**（全局树 / 命令目录 / 审计 / 设置）→ 归 **v3-3**；本叶只提供「状态栏入口面板 + 计数」的骨架位。
- 不做页面侧任何 UI / 手势 / 拾取实现（Alt 悬停 / Alt 拖动 / 右键自绘 / 拖选气泡 / 双向联动）→ 归 **v3-4**；本叶只做「从页面拾取」**入口**（禁用态由风险状态驱动，未授权 / 探测中时禁用）。
- **不**新增静态权限、**不**引入 `contextMenus`、**不**改安全判定链与 `content.js`、**不**删任何既有能力与既有断言、**不**以放宽密度上限换功能（父 NG-V3-001~017）。

### 2.3 与父规范的关系

- **权威条文在父 spec**：本文件只做「范围 / 依赖 / 验收锚点 / 独立性」切片；FR / NFR / AC 原文与口径定义以父 spec 为准（§5.2 / §8.1~8.2 / §9）。
- **编号**：沿用父的 `FR-V3-*` / `AC-V3-*` 编号，**不新增编号命名空间**（父 §2.3）。

## 8. 独立性说明（**能独立做到全门禁绿**）
