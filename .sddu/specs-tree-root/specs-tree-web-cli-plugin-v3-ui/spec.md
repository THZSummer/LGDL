## 2. 上下文

### 2.1 需求之源（**作者原话逐字留存，不得转述走样**）

| 日期 | 来源 | 原话（逐字引用） |
|------|------|----------------|
| 2026-09-15 | 作者真机反馈（反馈 1） | 「web-cli-plugin 的整个 UI 布局还是比较凌乱，没有条理」 |
| 2026-09-15 | 作者真机反馈（反馈 2） | 「让人感觉你这个系统**很复杂、很难用，信息密度太高了**，逻辑上应该是**随用随取**，所谓『**渐进式披露**』」 |
| 2026-09-15 | 作者设计取向 | 「按照 E 的思路」（指 `design/ui-redesign/option-e-progressive.html`） |

作者是插件当前**唯一真实用户**（A-UI-009；样本量为 1 为已知局限，如实登记）。本 Feature 要解决的核心问题 = 默认首屏信息密度压倒一切 · 信息缺乏稳定层级与归属 · 五类高后果信息无永不折叠常驻位 · 能力增长与侧栏容量的结构性矛盾（Q-UI-001~004）。

### 2.4 目标用户

| 角色 | 场景 | 本 Feature 的改善目标 |
|------|------|---------------------|
| **日常站点使用者（首位真实用户 = 作者本人）** | 在已授权站点打开侧栏，想「让插件在这页上做一件事」 | 默认首屏只回答「下一步做什么」；不再需要自己在满屏信息里筛选 |
| **窄侧栏使用者（320–560px）** | 侧栏拖到 320px 仍要完成同一批任务 | 320px 下零水平溢出 **且** 常驻元素不删（只允许文案截断）；披露层保证可达 |
| **新用户 / 生态用户（后续 web-cli 站点用户）** | 首次安装：onboarding + discovery-notice + 空态 | 首装态有独立密度档（≤9 可点 / ≤20 行），不让首屏先变成满屏功能 |
| **维护者 / 开发者（AI Agent + 作者）** | 每次 UI 改动都要跑门禁 | 新增机器可复算的密度门禁 + 断言取代台账；每个叶子可独立做到全门禁绿 |

## 7. 边界情况 (EC)

| ID | 场景 | 处理方式 |
|----|------|---------|
| **EC-V3-001** | **引用失效**（O-UI-002 fail-closed）：元素从 DOM 消失 / origin 变更 / 页面导航（含 SPA 路由）/ 站点声明版本变化 / 授权被撤销 / 判定不确定 | 一律判定为**失效**（fail-closed），进入 L0 风险位（永不折叠）+ 给出**可读原因**（哪一维触发）；阻断用失效引用发起动作；提供「重新拾取」（≤1 次交互）与「改用描述」两条恢复路径（FR-V3-036~038） |
| **EC-V3-002** | **硬底线被拦不可覆盖**（`evaluate` / 未授权 origin / 未知 risk） | L0 显示「被拦 + 原因」；**不提供任何允许 / 放行控件**；解释文本在 L1；不得因为「密度低」而省略该行（D3 优先于全部其他规则） |
| **EC-V3-003** | **未授权站点零注入** | 不注册 content script、不注册监听、不渲染拾取层 / 气泡 / 自绘菜单、不拦截右键；L0 风险位明示「未授权」+「页面侧零注入」；「从页面拾取」入口禁用（FR-V3-014 / FR-V3-068） |
| **EC-V3-004** | **可选权限未批准**（`bookmarks` / `clipboardRead` / `clipboardWrite` / `downloads` / `notifications`） | 相关能力入口**可见但禁用** + 可读原因（未授予）+ 申请入口（≤1 次交互）；**禁止静默隐藏**（违反 D6）；未授予时不得降级为其他权限路径 |
| **EC-V3-005** | **站点无声明 / 版本不兼容** | L0 风险位显示「探测中」或「无声明」；探测期间**不发命令**；不渲染页面侧拾取 UI；给出可读下一步（如「等待站点声明」/「手工绑定」） |
| **EC-V3-006** | **元素在操作过程中消失**（悬停 / 拖动 / 拾取过程中目标被重渲染或卸载） | 立即转入失效路径（EC-V3-001）：撤销高亮、标记引用失效、不发命令；若动作已进入确认阶段则回到「未执行」，并在回执中如实登记「目标失效未执行」 |
| **EC-V3-007** | **扩展重载 / 服务工作者休眠** | 恢复后重新解析授权与引用有效性；无法确认的引用一律按失效处理（fail-closed）；不得回放已失效引用；展开态允许重置（重置须在状态栏/回执中可见，不静默） |
| **EC-V3-008** | **320px 极窄侧栏** | 零水平溢出必须成立；**不删任何常驻元素**（含五类风险位与状态栏）；只允许文案截断（省略号）、缩小步长与换行；**禁止**为省空间把风险信息改为 tooltip 或仅图标 |

## 9. L0 密度口径（机器可复算定义）与反证要求

> 本节是本 Feature 的**核心验收定义**（D7）。口径与 `design/ui-redesign/index.html` 的实测口径**同源**；任何实现必须能按本节逐条复算，且门禁必须能**真 FAIL**。

### 9.1 四项口径（定义，逐条可复算）

测量根 = 面板根元素（L0 默认态的整个侧栏面板）。

| # | 指标 | 定义 | 反作弊 / 边界规则 |
|---|------|------|------------------|
| **C1** | **可点元素数（clickables）** | 满足下列两条的元素计数：① **不在任何 `hidden` 属性为真的祖先子树中**；② 标签名为 `button` / `a` / `input` / `select` / `textarea` 之一，或存在 `tabindex` 属性且值 ≠ `-1` | **仅当祖先含 `hidden` 属性才豁免**；`display:none` / `visibility:hidden` / `opacity:0` / `pointer-events:none` / 移出视口 / `aria-hidden` **一律不豁免**（仍计入）——防止用 CSS 隐身或位置移出刷低密度 |
| **C2** | **可见正文行数（visible body lines）** | `⌈ Σ(可见元素「自身直接文本」去空白后字符数) ÷ 34 ⌉`。**自身直接文本** = 元素直接子文本节点（不含后代元素文本），每个元素只计一次 | `34` = 320px 宽、13px 字号下每行约 34 字（保守取整，E 稿口径）；可见性判定同 C1；文本块内的模板占位符（`{{…}}`）不计 |
| **C3** | **可见文本块数（visible text blocks）** | 「自身直接文本去空白后非空」且**可见**（判定同 C1）的元素个数 | 只计数、**不设上限**（用于跨版本对照与反作弊交叉验证） |
| **C4** | **面板常驻分区数（resident zones）** | 面板**一级子元素**中非 `hidden` 的个数 | **不设上限、不视为越小越好**（见 §8.1 口径说明：E 比 D 多 1，因风险位独立成区）；只做「变化登记 + 反作弊」 |

### 9.2 阈值（本 spec 采用值）

| 档 | 状态定义 | C1 可点元素 | C2 可见正文行 | C3 / C4 | 视口 |
|---|---|:--:|:--:|---|---|
| **L0 默认态** | 已绑定 + 已授权 + 探测完成 + 无待确认 + onboarding 与 discovery-notice 已终结 | **≤ 7** | **≤ 15** | 只登记，不设限 | 320 / 400 / 520 |
| **L0 首装态** | onboarding 或 discovery-notice 生效中 | **≤ 9** | **≤ 20** | 只登记，不设限 | 320 / 400 / 520 |
| **L0 风险态** | 五类风险信息任一生效 | **≤ 17** | **≤ 35** | 只登记，不设限 | 320 / 400 / 520 |
| **L0 全展开态**（对照） | 全部 L1 / L2 展开 | 不设上限（仅登记） | 不设上限（仅登记） | 只登记 | — |

**阈值取值说明（可追溯）**：

1. **默认态 7 / 15**：`7` 取自 E 稿同口径实测（可点元素 7）；`15` 取自 E 稿法则 1 的原文上限（「可见正文 **不超过约 15 行**」，E 实测约 10 行为裕量）。**采用理由**：与作者「按照 E 的思路」的设计基准一致，且属于**收紧方向**（E 实测 10 < 上限 15）。
2. **首装态 9 / 20**：v1 的 onboarding 与 discovery-notice 属**已验收行为、不删**（NG-V3-005），因此需要独立档；`9 / 20` = 默认档 + 2 个可点元素（「下一步」/「知道了」类）+ 5 行（说明文案）。**该档由本 spec 设定**（设计稿未覆盖首装态），属 spec 级新口径，须在 plan 中落成可测断言。
3. **风险态 17 / 35**：**= 默认档 + 风险增量预算**（可点 **+10** = 五类风险各至多 1 个「为什么 / 详情」入口〔5〕+ 破坏性确认选项至多 5 个；行 **+20** = 五类风险各至多 4 行文本）。**采用理由**：直接兑现 E 稿原则 4「**密度可以让步，风险不让步**」——风险信息不受默认档上限约束，但**仍必须有有限上限**（否则门禁无法 FAIL）。**附加硬约束（反作弊）**：风险增量预算**只能被风险类元素占用**，出现任何非风险类新增可点元素 / 文本块即 FAIL（AC-V3-003）。
4. **不设「分区数上限」**：见 C4 与 §8.1——风险位独立成区使 L0 分区数**高于** D 稿（6 > 5），若把分区数当密度指标会得出「E 比 D 更密」的错误结论。

### 9.3 反证要求（**门禁必须能真 FAIL**，NFR-V3-013）

| # | 反证 | 期望结果 | 备注 |
|---|------|---------|------|
| **RP-V3-01** | 在 L0 默认态注入 1 个额外可点元素（临时 `<button>`） | 密度门禁 **FAIL**，输出实测值 / 上限 / 口径 | 还原后 PASS；全过程留日志 |
| **RP-V3-02** | 将默认态上限常量人为调低 1（7 → 6），不改 DOM | 密度门禁 **FAIL** | 证明阈值真参与判定（不是被忽略的常量）；还原 |
| **RP-V3-03** | 把一个原本计入的可点元素改用 `display:none`（或 `visibility:hidden`）隐藏，**不用** `hidden` 属性 | 计数**不下降**（仍计入）→ 门禁保持与改动前一致的判定；若计数下降则 **FAIL**（说明 C1 被绕过） | 与 AC-V3-006③ 对应 |
| **RP-V3-04** | 把某类风险信息移入一个 L1 展开层（`hidden`） | AC-V3-008 / AC-V3-009 **FAIL** | 风险永不折叠的反证 |
| **RP-V3-05** | 删除 1 条既有断言 | 取代台账门禁 / 计数下界守卫 **FAIL** | AC-V3-014 |
| **RP-V3-06** | `dist/content.js` +1 B | 体积门禁 **FAIL** | AC-V3-015 |

> **纪律**：以上反证**必须实跑**（不得只写在文档里）；日志必须完整落盘（**禁 tail 截断**）；门禁**严格串行**执行（禁并发 Chromium）。

### 9.4 口径与阈值的变更纪律

- 四项口径（C1~C4）**不得**为使门禁变绿而修改；确需修改必须走「需求修订 + 前后口径对照 + 与设计稿口径的同源性说明」。
- 三个档位的阈值只允许**收紧**；放宽必须由作者/编排器裁决并显式登记（前后值 + 日期 + 理由 + 历史保留），且**不得**以放宽上限换功能（NG-V3-010）。
- 首轮**真实产物复测**（对照 A-UI-001）必须把实测值登记为基线（前后值 + 日期 + 来源 + 三档视口），并与设计稿口径数字**分开记录**（设计稿口径 ≠ 真实产物口径）。

## 10. 既有断言取代策略与取代台账（R-UI-002）

> 背景：`test:ui` journey **167** 运行时断言 / `test:insight` **108** / `test:binding` **192** 大量通过 `querySelector` / `getElementById` **直接钉住当前 sidepanel DOM**（实测：journey 32 / 134，insight 118 / 42，binding 25 / 63），另有 `test/sidepanel-view.test.ts` **38** 用例（含 **4** 项布局 / 样式契约：三分区、`#log.empty:not(:has(> *))`、`#panel-main` / `#log` CSS 断言、composer 为底区最后子元素）。任何 UI 重设计都必然打破它们。**纪律 = 零删除、零降级**。

### 10.1 取代策略（逐门禁处置原则）

| 门禁 | 规模 | **处置原则（本 Feature 强制）** |
|------|------|------------------------------|
| `test/ui/journey.mjs`（`test:ui`） | **167** 运行时断言 | **零 diff 优先**：沿用既有 `policy = zero-diff` —— journey.mjs **保持零改动**。若某条断言语义确实被新界面取代（例如引用了已迁移的 DOM id），**只允许**「同编号 old → new 改写 + 台账登记」，**总数不减（≥167）**，**禁止删除、禁止降级为弱断言**（例如把「元素存在且可见」改成「页面能加载」） |
| `test/ui/insight.mjs`（`test:insight`） | **108** 运行时断言 | **新断言落新文件**：v3 新增断言落在**新增**的 v3 专用门禁文件（不修改 `insight.mjs` 既有条目）；被取代的旧条目**逐条登记** old → new（含 reason），`count ≥ 108`。本门禁是取代的**最大战场**（树 / 回执 / 确认相关断言集中于此） |
| `test/ui/binding.mjs`（`test:binding`） | **192** 运行时断言 | **既有编号零删改**（`#21*` / `#22*` 系列原样保留）；新断言**追加新编号**（建议 `#23a…` 起）；`count ≥ 192` |
| `test/sidepanel-view.test.ts` | **38** 用例（含 **4** 项布局 / CSS 契约） | 静态文本断言**允许随 DOM 契约迁移**（因为 DOM 结构必然改变），但必须① 逐条 old → new 登记；② 用例数 ≥ 38；③ **4 项布局 / 样式契约必须逐项仍被断言**（可替换为等价或更强断言，例如 CSS 收敛为等价选择器断言），**不得**因为「DOM 变了」直接删掉契约 |
| 计数下界守卫 `test/insight-tree-hierarchy.test.ts#currentNodeTestCount()` | 要求 `current ≥ 646` | **保留并只增不减**（本 Feature 不得下调该下界） |
| 安全 / 硬底线类断言 | 分散 | **只增不减**（新增 UI 面必须补反向断言，例如「提权控件计数 = 0」「伪造消息不能突破 clamp」） |

### 10.2 取代台账（**落点与 schema**）

- **落点**：仓库内一份**机器可读 JSON**，沿用既有先例 `packages/web-cli-plugin/docs/r2-supersession-ledger.json` 的**目录与 schema**；本 Feature 建议新建 `packages/web-cli-plugin/docs/v3-supersession-ledger.json`（**具体文件名由 plan 确认**，但必须：可被门禁读取、纳入版本库、与 v2 台账并列不覆盖）。
- **schema（沿用 r2 先例，逐条一条记录）**：`oldId` / `oldTitle` / `newId` / `newTitle` / `gate`（所属门禁）/ `reason`（为何取代）；台账顶部必须含 **`counts`** 字段（各门禁取代前后计数 + **口径说明**，避免跨口径混用——v2 已出现过「646 / 690 / 693」跨口径歧义，本 Feature 必须显式标注口径）。
- **门禁**：受保护文件的**任何删除行**必须命中台账某条记录的 `oldId` / `oldTitle`；未命中即 **FAIL**（AC-V3-011）。同时校验 journey.mjs 零 diff（或仅命中台账的改写）与各计数下界（AC-V3-012）。
- **禁止**：把台账当成「先删后补理由」的橡皮图章——台账条目的 `newTitle` 必须指向**真实存在且强度不降**的新断言。

### 10.3 「每个叶子结束时全部门禁必须绿」

- **强制**（FR-V3-003 / AC-V3-013）：4 个叶子**逐个**完成，每个叶子收尾时必须跑完全部门禁（**串行**）且全绿，才允许下一个叶子开工；
- 禁止把未取代的红灯遗留给下一个叶子（EC-V3-013）；若某叶子确实无法在同一叶内完成取代，**必须**先缩小该叶范围并显式登记，而不是留下红灯。

### 11.1 依赖与交付顺序（**严格串行门禁，执行顺序建议**）

```
v3-1（L0 骨架 + 密度门禁 + 风险位）
   │  ← 首个开工；产出「L0 密度口径可测基线」（补充 1，避免设计稿数字直接当验收值）
   ├──────────────┬──────────────┐
   ▼              ▼              │
v3-2（L1）     v3-3（L2）        │   ← 两者都只依赖 v3-1 的折叠器/摘要契约；
   │              │              │     可并行分解，但**门禁执行必须串行**
   └──────┬───────┘              │
          ▼                      │
        v3-4（页面即输入）  ←──────┘  ← **最后开工**：R-UI-001 / R-UI-004 / R-UI-008
                                       三条风险全部集中于此；需前置 spike 通过后
                                       再动，且**不得**放宽体积上限换功能
```

| 顺序 | 叶子 | 前置 | 独立性说明（**能独立做到全门禁绿**） |
|:--:|------|------|-----------------------------------|
| 1 | v3-1 | 无（首个） | 只改侧栏默认骨架与新增密度门禁；风险位独立成区不新增权限、不碰页面侧；既有断言取代量最小（L0 骨架 + 密度断言新文件） |
| 2 | v3-2 | v3-1（L0 折叠器 / 摘要契约 + 密度基线） | 纯 L0 → L1 就地展开；不触碰 L2 视图与页面侧；引用失效判定在侧栏侧即可完整验证（页面侧只需注入「元素消失」事件） |
| 3 | v3-3 | v3-1（状态栏入口 + 折叠器契约） | 复用既有 tree-drawer / 命令档案 / 审计 / 设置实现，主要工作是改归属 + 补计数入口；是取代台账**最大战场**，需预留取代工作量（但不与其他叶耦合） |
| 4 | v3-4 | v3-1（选择题与引用 chip 契约）+ v3-2（引用证据 / 失效呈现） | 与 L0/L1/L2 解耦（页面侧 vs 侧栏侧）；唯一触碰 `content.js` 的叶子，**必须独立证明**体积零增长 + 零注入 + 三退让 |

**父 Feature 定位（复核确认）**：父 = 轻量规范容器（聚合 spec 与 review / validate 汇总报告），**不承接 tasks / build / review / validate 类阶段操作**（与 v2 先例一致：v2 父保持 `phase=tasked`，仅承载聚合报告）。

**未采纳的调整提议（已评估放弃）**：曾考虑把「密度门禁」独立成第 5 个叶子；放弃理由 = 密度口径依赖 L0 骨架（v3-1 的产物），独立成叶会产生对 v3-1 的强依赖而无法独立全绿，违反「每叶可独立全绿」约束。
