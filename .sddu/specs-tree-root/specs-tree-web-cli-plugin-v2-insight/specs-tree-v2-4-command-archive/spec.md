> **文档定位**: SDDU 需求规范（**叶子子 Feature**）— 定义 V2-4 的功能/非功能需求与验收边界，作为 plan 阶段的输入
> **前置依赖**: 父 Feature `specs-tree-web-cli-plugin-v2-insight/spec.md`（v1.0，2026-09-13）——本子 Feature 的需求为**父 spec 的 FR-V2-050~FR-V2-056**；上游依赖 V2-1（树模型中的命令投影）
> **创建人**: SDDU Spec Agent · **创建时间**: 2026-09-13 · **版本**: v2.0 · **更新人/时间**: SDDU Spec Agent / 2026-09-13
> **更新说明**: v1.0 初始创建（随父 Feature 立项；P1 后段）。**v2.0 = R2 需求修订轮（post-validate，不回退 phase；依据作者 2026-09-13 偏差反馈，逐字见父 `spec.md §2.2b`）**：档案从「结构无控件只读面」改为**分层**——**硬底线 `deny` 仍无控件**（不可放宽）+ 原因可读；**非硬底线 `deny` / 普通命令有 `allow`/`ask`/`deny` 控件**（写入归 V2-3，档案提供**默认档 vs 覆盖生效档分列**）；覆盖面口径**分列**（实时面 122 卡 vs 基线 34/142）；承载父 `FR-V2-077/079`（档案侧）。原「不做命令级覆盖 / 只读展示」**作废/范围重定**（历史保留 + 「以现状为准」）。**其余条文不重写。**

## 2. 上下文与边界

**为什么存在**：作者原话「总共有哪些 cli 命令，那些 allow、哪些 ask、哪些 delay」。V2-4 为**每条命令**建卡：处置档 + risk 档 + 来源 + `delayMs` + 抑制态；`deny` **三成因分列可读**。

**边界（做什么 / 不做什么）**

| ✅ 做什么 | ❌ 不做什么 |
|-----------|-------------|
| 覆盖对账基线 **34 工具 / 142 子命令**并逐条有档；**[R2] 与实时投影面 122 卡口径分列、不夸大** | **不把「硬底线 `deny`」渲染成「用户可关的开关」**（不可放宽）；**[R2] 非硬底线 `deny` 可改回（有控件）** |
| `deny` 三成因分列（未授权 S1 / 未知或非法 risk S3 fail-closed / `evaluate` 硬底线）+ `auto-authorize` 的 `hardDeny` | **[R2] 不做绕过硬底线 clamp 的覆盖**（覆盖写入归 V2-3；档案给出**默认档 vs 覆盖生效档分列**） |
| 与 `test/parity.test.ts` 同源，纳入机器对账（新增/丢失命令即失败） | **不预设站点 runtime 行为**（档案只读真值） |
| `delay` 撞词消歧文案；来源标注；抑制态标注；可检索/过滤 | 不改判定链本体 / 不放宽门禁 / 不新增权限 |

## 3. 目标与非目标

**Goals**：G1 142 子命令逐条有档；G2 `deny` 三成因分列可读；G3 与 parity 同源机器对账；G4 `delay` 撞词消歧；**[R2] G5 默认档 vs 覆盖生效档分列 + deny 控件分层 + 覆盖面口径分列**。
**Non-Goals**：~~NG1 可关的 `deny` 开关~~ **【R2 范围重定，以现状为准】** → **NG1R 可关的「硬底线 `deny`」开关**（硬底线不可放宽；非硬底线 `deny` 可改回）；~~NG2 命令级覆盖~~ **【R2 作废，以现状为准】** → **NG2R 绕过硬底线 clamp 的覆盖**（覆盖写入归 V2-3）；NG3 放宽门禁；NG4 预设站点 runtime；NG5 改判定链本体。

## 4. 功能需求

> 本子 Feature **直接承载父 spec 的以下 FR**（权威条文见父 `spec.md §5.5`）：

| 父 FR | 一句话 | 子级验收补充 |
|-------|--------|-------------|
| FR-V2-050 | 每条命令有档（34 工具 / 142 子命令）：`allow`/`ask`/`delay(=deny)` + risk + 来源 + `delayMs` + 抑制态**〔R2·口径分列，以现状为准〕** | 覆盖率 **100%**；34/34 工具；**[R2] 实时面 122 卡与基线分列、不夸大** |
| FR-V2-051 | `deny` 三成因分列可读（S1 未授权 / S3 未知或非法 risk / `evaluate` 硬底线）+ `hardDeny` | 每个 `deny` 标注成因类别；分类正确 |
| FR-V2-052 | 不把**「硬底线 `deny`」**渲染成可关开关**〔R2·范围重定，以现状为准〕** | **[R2] 硬底线 `deny` 零控件 + 原因可读；非硬底线 `deny` 有控件可改回**；无绕过 clamp 写入 |
| FR-V2-053 | 与 parity 同源机器对账（新增/丢失命令即失败） | 判定表与 `policy.ts`/`auto-authorize.ts` 一致；双向 + 子命令级 |
| FR-V2-054 | `delay` 撞词消歧文案 | 文案：「`delay`（= `deny`，fail-closed，非可配置档位；与命令间 `delayMs` 无关）」；`delayMs` 独立列 |
| FR-V2-055 | 来源标注（base 内建 / `site_*` / 插件 `admin_*`·`tabs`·`bookmarks`·`downloads`·`notify`·`clipboard`） | 与注册真值一致；`site_*` 标注所属 origin |
| FR-V2-056 | 抑制态标注 + 可检索/过滤 | 抑制态与 `deriveTools()` 一致；检索只读 |
| **FR-V2-077** **[R2·档案侧]** | **`deny` 控件分层（档案）**：硬底线 `deny` → 无控件 + 不可覆盖原因可读；非硬底线 `deny` → 有 allow/ask 控件（写入归 V2-3）；档案展示**默认档 vs 覆盖生效档**分列 | 分层断言；默认档/生效档分列；硬底线原因文案 |
| **FR-V2-079** **[R2·档案侧]** | **覆盖面口径分列**：实时投影面 **28/94=122 卡** vs parity 基线 **34/142** 分列；`accounted` 口径不渲染；不夸大 | 分列字段/展示断言；「已全部渲染」类表述零命中 |

**`delay` 消歧（红线文案，必须原样落成）**：
> `delay`（= `deny`，fail-closed，**非可配置档位**；与命令间 `delayMs` 无关）

## 6. 边界情况

| ID | 场景 | 处理 |
|----|------|------|
| EC-V24-001 | risk 未知/非法/缺失 | 展示 `deny` + 成因 S3（**不可关，亦不可覆盖为 allow**） |
| EC-V24-002 | 命令集合与基线漂移（新增/丢失） | 对账 FAIL；以 `deriveTools()` + registry 为真值 |
| EC-V24-003 | 命令被开关/授权状态抑制 | 标注抑制态（不误报为可执行） |
| EC-V24-004 | `site_*` 工具所属站点未授权 | 归属 S1 deny 成因并标注来源站点 |
| EC-V24-005 | 用户把 `delay` 误读为「待批准/可配置延迟」 | 消歧文案完整可读（AC-V24-005） |
| EC-V24-006 **[R2]** | 用户覆盖命中硬底线 | 档案展示**覆盖生效档 = 硬底线值**（clamp 后）+ 不可覆盖原因可读；不显示为已 allow |
| EC-V24-007 **[R2]** | 口径夸大风险（把实时面说成基线） | 实时面 122 卡与基线 34/142 分列；「已全部渲染」类表述零命中（AC-V24-008） |
