本叶 = v4 的**承载层内化**：把 `ask-user`（choice/text）与破坏性二次确认从「流之上的独占决策槽」迁入**流内卡**并固化不可逆，把 60 s 超时 / 取消 / `supersededAsk` 全部升级为**留痕**，并让授权记录在流内可回看。这是作者原话「所有过程性的问答…同时也方便看到授权记录，不要放到上面，丢失过程信息」的直接兑现。

## 2. 上下文与边界

### 2.1 上下文

父核心问题 Q-CHAT-001（承载层）= `ask-user` 与破坏性确认渲染在 `#l0-decision`（`#log` 的**前一个兄弟节点**，结构上位于流之上）且 `resolveAsk`/`resolveConfirm` 后置 `null` → **解析即消失**；Q-CHAT-002 = 唯一「已决策历史」是 L1 面板 `rounds[]`（仅内存、只覆盖 ask、默认 `hidden`）；Q-CHAT-007 = R1 的 `supersededAsk` 只做「取消」不做「留痕」；R-CHAT-007 = ask 迁移后的 busy/回合语义；R-CHAT-008 = 留痕与既有零明文红线冲突。本叶是作者主诉的**直接对应物**。

### 2.2 范围（做 / 不做）

**做（in）**：

- `ask-user`（choice / text）从独占决策槽迁入**流内**卡；删除「同时只允许一张、旧卡不滞留」独占语义（父 FR-CHAT-040）。
- `ask` 卡操作前/后固化（`data-answered` + 表单收起 + 固化区「已答：+ 内容」+ 时间戳）（父 FR-CHAT-041）。
- 已固化卡不可二次回答；取消也留痕（「已取消（不代填默认值）」）（父 FR-CHAT-042）。
- 60 s 超时 → `canceled` 留痕、不代填默认值（父 FR-CHAT-043）。
- **`supersededAsk` 升级为「取消 + 留痕」**（父 FR-CHAT-044）。
- 破坏性二次确认（`confirm`）迁入流内 `auth` 卡；批准/拒绝固化（父 FR-CHAT-045）。
- 授权卡含范围与后果预演 + 审计入口；已决策不可重复；旧卡不消失（父 FR-CHAT-046）。
- 授权记录流内可回看；与审计视图分工（父 FR-CHAT-047）。
- busy / 回合语义规则（多张未答卡、`pending` 门控、与拾取/会话切换关系）（父 FR-CHAT-048）。
- 流内留痕零明文边界（父 FR-CHAT-049）。

**不做（out）**：

- 不做事件模型与卡渲染基础（v4-2）、不做引用/系统/推荐卡（v4-4）。
- 不做站点级授权 / 撤销 / 会话与分组 / 隐私开关 / 知情同意 / 自动授权开关的**归属实现**（法则六 → 设置/审计视图，归 v4-1 的工具栏准入 + 设置视图）；本叶只处理**单次操作授权卡（confirm）**与会话上下文内的问答。
- 不改判定链（`policy.ts`/`auto-authorize.ts`）、不新增权限、不碰 `src/content/**`、不降级既有安全断言。
- 不做体积绝对上限闭合（父收口锚）。

### 2.3 与父规范的关系

- 权威条文：父 §5.5（FLOW）+ §10（取代台账）+ §8.3（AC）。
- 本叶依赖 v4-2 的事件模型与固化契约，但**不依赖** ref/system 两类卡的迁移（与 v4-4 可并行分解，门禁串行）。
- 本叶遵循父 §12 裁决：O-CHAT-002（id 口径 / 会话切换 / 留痕持久化范围留给 plan）、O-CHAT-005（法则六：管理的归视图、会话过程的归流内卡）、O-CHAT-008（askuser/auth 为 7 主类成员）。

## 3. 目标与非目标（本叶）

### 3.1 目标

| # | 目标 |
|---|------|
| G1 | 问答与破坏性确认**不再出现在流之上**，全部在流内固化留痕 |
