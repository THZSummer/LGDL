## 2. 上下文与边界

### 2.1 上下文

父核心问题 Q-CHAT-003 = 「下一步推荐」能力完全缺失（无生产者/无通道/无 UI，grep 零命中）；Q-CHAT-005 = 系统事件散落 6+ 条瞬时通道、无时间戳、可被覆盖；Q-CHAT-006 = 引用生命周期投影到 3 个互不相邻位置、流内无引用卡；Q-CHAT-013 = 面板侧拾取入口消失带来的可发现性/救援路径断裂（R-CHAT-012）。本叶把这三类过程补齐，并执行父级体积收口锚。

### 2.2 范围（做 / 不做）

**做（in）**：

- **引用卡**：有效/失效；失效卡保留；新引用序号递增（父 FR-CHAT-050）。
- 重拾 / 重锚生成新引用卡（新 id + 序号递增）+ 旧引用零改动（沿用 R3 append-only 先例）（父 FR-CHAT-051）。
- 失效卡含失效原因 + 两条恢复路径（「重新拾取」/「改用描述」，兜底默认收起）（父 FR-CHAT-052）。
- **系统事件行**：单行 + `HH:MM:SS` 时间戳 + 只追加、不被覆盖（父 FR-CHAT-053）。
- 6+ 条瞬时通道归并（`#env-guard`/`#site-hint`/`#onboarding`/`#discovery-notice`/`#notice`/`#send-reason` + 导航失效 + 探测态）（父 FR-CHAT-054）。
- 拾取入口迁移后的**可发现性与救援路径重锚**（页面侧可达、未授权路径可发现、`l1/panels.ts:259` 的 `#l0-pick.click()` 复用点断裂处置）（父 FR-CHAT-055）。
- **推荐卡**：生产者机制（真值派生，不新增 LLM 产物）+ chips 即指令 + 规则表/优先级/上限 + 无候选不渲染 + 与 `pending` 门控一致 + 安全边界（父 FR-CHAT-060~064）。
- **V3-VOL-3 父级收口锚**：重定 sidepanel 基线（五要素）+ 绝对上限带值闭合（推导规则 + 作者确认）（父 FR-CHAT-090~094）。

**不做（out）**：

- 不做事件模型/卡渲染基础（v4-2）、不做 ask/授权业务（v4-3）。
- 不做三区骨架与密度口径（v4-1）。
- 不新增 LLM 侧产物（推荐若必须 LLM 则属新面，显式登记不隐含）；不新增权限；不改判定链；不碰 `src/content/**`、不碰 `pick-layer.js`。
- 不删除或降级任何既有断言；不以放宽体积上限换功能；不设自缚装置。

### 2.3 与父规范的关系

- 权威条文：父 §5.6（TRACE）+ §5.7（NEXT）+ §5.10（VOL）+ §10.4（体积义务落位）+ §8.3 / §8.6（AC）。
- 本叶依赖 v4-2 的模型与卡渲染，与 v4-3 无强耦合（可并行分解，门禁串行）。
- 本叶是本 Feature 的**父级收口锚执行叶**：V3-VOL-3 带值闭合由本叶在其收口轮执行（父 §10.4 / §11.1）。
- 本叶遵循父 §12 裁决：O-CHAT-002（ref 卡 = 引用注册表投影 + 事件记录）、O-CHAT-004（绝对上限推导规则）、O-CHAT-006（推荐真值派生 + chips 即指令）、O-CHAT-009（竞品非阻塞）。
