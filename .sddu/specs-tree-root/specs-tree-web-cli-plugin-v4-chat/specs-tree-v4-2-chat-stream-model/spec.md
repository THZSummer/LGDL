# Feature Specification：specs-tree-v4-2-chat-stream-model（V4-2 聊天流 append-only 事件模型与卡渲染）

> **文档定位**: SDDU 需求规范（叶子切片） — 本叶承载的父 FR / NFR / EC / AC 的**实施范围切片**；权威条文见父 `../spec.md`
> **前置依赖**: 父 `../spec.md` v1.0（2026-09-18）+ 父 `../discovery.md` v1.0；**v4-1**（三区骨架 + 密度新口径基线）；设计基准 F 稿 + shim 60 断言

本叶 = v4 的**模型与渲染地基**：把流事件模型做成不可变、单调、可回放的 append-only，落 7 主类 + 过程卡族的渲染与统一固化契约，并把既有 5 种过程形态（工具卡 / 命令行 / 思考指示 / 错误条目 / 工具通知）**零丢失**归位。本叶不依赖 SW 契约变更（可先用既有 5 条通道喂数据），是 v4-3 / v4-4 的共同地基。

## 2. 上下文与边界

### 2.1 上下文

父核心问题 Q-CHAT-001（模型层）= 过程条目「解析即消失」；Q-CHAT-007 = 独占决策槽覆盖旧回合；Q-CHAT-005 = 系统事件无统一承载；R-CHAT-006 = append-only vs 既有可变 state 的迁移；R-CHAT-013 / O-CHAT-008 = F 的 7 类卡与现状 5 种过程形态的分类学缺口；R-CHAT-014 = 固化可交互性/无障碍回归。本叶把流做成**唯一承载面**的模型与渲染基础。

### 2.2 范围（做 / 不做）

**做（in）**：

- **流事件模型**：不可变、id 单调（统一 `nextId`）、可回放；删除「解析即置 `null`」路径；类型集合 = 7 主类 + 过程卡族（父 FR-CHAT-020 / FR-CHAT-021）。
- **卡渲染与固化契约**：`data-*` 状态属性 + `[hidden]` 切换表单/固化区 + `.ts` 时间戳 + `.card-fixed`（父 FR-CHAT-022）。
- **只固化不撤销**：无撤销控件；撤销 = 新系统事件行（父 FR-CHAT-023）。
- **会话切换不丢过程元数据**（`tool`/`ok`/`ms` 保留；截断规则显式登记）（父 FR-CHAT-024）。
- **留痕完备性 + 可回放**（父 FR-CHAT-025）。
- **7 主类卡**（`ai`/`user`/`nextstep` 骨架/`askuser` 骨架/`auth` 骨架/`system`/`ref` 骨架）与**过程卡族**（`tool`/`command`/`thinking`/`error`/`notice`）渲染（父 FR-CHAT-030~037）。
- **消息契约扩展不进 `KIND_SET`**：沿用独立校验器模式（父 FR-CHAT-026）。
- 滚动跟随/回看（`scroll-policy` 48px）、320px 流内长卡换行（本叶相关 NFR/EC）。

**不做（out）**：

- 不做 ask-user / 授权卡的**流内化与业务逻辑**（choice/text 提交、批准/拒绝、60s 超时、supersededAsk）→ 归 v4-3（本叶只提供 `askuser`/`auth` 卡**渲染骨架与固化契约**）。
- 不做引用卡的**引用判定 / 重锚业务**（`ref-store` 五维判定、R3 救援）→ 归 v4-4（本叶提供 `ref` 卡渲染骨架与序号递增的**投影接口**）。
- 不做系统事件的**6+ 通道归并业务**与推荐卡的**生产者**→ 归 v4-4（本叶提供 `system`/`nextstep` 卡渲染骨架）。
- 不做三区骨架与密度门禁（v4-1）、不做体积绝对上限闭合（父收口锚）。
- 不改判定链、不新增权限、不碰 `src/content/**`、不降级既有断言。

### 2.3 与父规范的关系

- 权威条文：父 §5.3（STREAM）+ §5.4（CARD）+ §10（取代台账）+ §8.1 / §8.3（AC）。
- 本叶是 **v4-3 / v4-4 的共同地基**：事件模型与固化契约定稿后，两叶只做各自类型的业务填充与通道接入。
- 本叶遵循父 §12 裁决：O-CHAT-001（过程卡族折叠阈值 480/10；固化卡与系统事件行不压缩）、O-CHAT-002（id 口径 + ref 卡为注册表投影）、O-CHAT-008（7 主类 + 过程卡族）。
