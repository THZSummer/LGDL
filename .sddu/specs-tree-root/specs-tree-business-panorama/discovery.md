## G1 问题定义与产品定位（✅ 已定稿 2026-08-30）

### G1-Q1 「布局拉扯循环」的真实场景还原
- **原话**: "mermaid，布局方向，布局结构"
- **解读**: 痛点场景发生在使用 Mermaid 时，具体坏点集中在两个维度——「布局方向」（疑指 direction 声明与实际连线走向不服从）与「布局结构」（疑指节点排布/分组/连线关系混乱）
- **状态**: ⛔ 追问①用户跳过——未获得具体案例还原（哪张图/多少节点/几轮拉扯/每轮坏在哪），访谈不再追问。**已知空白点**：全景文档「痛点场景」段落只能停留在维度级描述，无具象故事；由作者后续自行补充或接受维度级表述

### G1-Q2 压垮决策的「那一下」
- **原话**: "现有的布局算法画出的效果不太好，实际业务场景下有时候极差"
- **解读**: 决策触发不是某次戏剧性失败，而是对「现有布局算法在真实业务图上的效果下限」的累积判断。关键信息在「有时候极差」——问题不是普遍差，而是**不可预测地差**，这意味着输出不可信任。与 Q1 拼合后构成完整动机链
- **状态**: ✅ 可用

### G1-Q3 「语义优先」的来源方向
- **原话①（动机）**: "AI布局效果不稳定，希望完全由程序固化"
- **追问②回答（术语来源）**: "设计好的" —— 动手写代码前，「语义优先」就已作为设计公理立下，非事后总结的标签
- **解读**: 动机链：AI 布局效果不稳定 → 需要确定性输出 → 布局权完全收归程序（与 facts-baseline §3.1 design.md:29「全量确定性布局，语义不变则输出不变」形成 Why↔What 对应）。叙事定性：**公理先行**——「语义优先」是先立的设计信念，痛点观察（AI 布局不稳定、现有算法效果极差）是信念的现实印证。全景叙事可按「设计公理 + 痛点印证」双层讲，而非纯痛点归纳
- **状态**: ✅ 已确认（含追问②）

### G1-Q4 「面向 AI」的定位有没有摇摆
- **原话**: "没有动摇，AI是绝对的核心"
- **解读**: 定位从第一天起即 AI-first，从未考虑「给人用、顺带 AI 友好」的折中路线。这是 design.md:73（「消费方是 CLI 操作的 AI，不是手写语法的开发者」）的决策源头：不是演化结果，而是立项时的既定公理
- **状态**: ✅ 已确认

### G1-Q5 不解决的后果推演
- **原话**: "不至于烂到什么程度，只是使用过程会无比煎熬"
- **解读**: 受访人主动校准了痛点烈度——不是「不可用/灾难」级，而是「工作流摩擦」级（无比煎熬）。诚实记录这一点对全景叙事有价值：LGDL 解决的是**效率与体验型痛点**，不是救火型痛点；但结合 Q2「有时候极差」，摩擦的烈度足以支撑立项决策
- **状态**: ✅ 已确认（含烈度校准信息）

### G1 小结（✅ 定稿）
- **核心问题链（Why 链）**: 「语义优先」为立项前设计公理（"设计好的"）→ 现实印证：Mermaid 等现有工具的布局算法在真实业务图上不可预测地差（"有时候极差"）、AI 布局效果不稳定 → 决策：语义留给 AI、布局完全固化给程序（确定性输出）→ 定位 AI-first 从未摇摆（"AI是绝对的核心"）
- **痛点性质**: 效率/体验型（"无比煎熬"），非可用性灾难型（"不至于烂到什么程度"）
- **已知空白**: Q1 具体案例还原被跳过——痛点场景仅有维度级描述（mermaid/布局方向/布局结构），无具象故事

## G4 语言设计的产品哲学（2026-08-30 已回填：5/6 作答，1 问跳过）

### G4-Q1 「不留兼容包袱」的底气
- **原话**: "用户量为零，内部孵化阶段"
- **解读**: 破坏性变更的成本评估很直接——用户量为零、内部孵化阶段，兼容包袱没有服务对象；语言纯度的收益 > 兼容的收益（无人受益）。这解释了 v0.4 两条「破坏性：旧写法不再兼容」（CHANGELOG.md:147/156）为何可以无痛落地
- **状态**: ✅ 已回填

### G4-Q2 为什么 error 不是 warning
- **原话**: "NO，警告的意思是可以容忍，意味着似有似无，不一定要遵守，错误不可容忍，必须严格按照规则执行，避免后续带来关联性错误"
- **解读**: 二元语义观——warning = 可容忍 = 规则可选择性遵守（似有似无）→ 会滋生**关联性错误**；error = 不可容忍 = 规则强制执行。放弃 warning 路线并非未考虑「对 AI 友好」，而是认为容忍性信号本身就是错误来源：规则一旦允许选择性遵守，后续错误会在别处爆发。与「零猜测」「严格校验」同属一个哲学：**不制造灰色地带**
- **状态**: ✅ 已回填

### G4-Q3 语法为什么是 YAML 风格缩进 DSL
- **原话**: "没有AI默认选的，如果JSON更好，可以选择更换"
- **解读**: 🚨 **AI 自主决策又一例**：YAML 风格缩进 DSL 是 **AI 默认选择**，作者未做过专项权衡（token 成本等未评估），且明确表态开放更换——「如果 JSON 更好，可以选择更换」。与 G3-Q5/Q6 同性质素材累积：**连语言语法形态本身也是 AI 决策产物**
- **状态**: ✅ 已回填 | **置信度: 低（AI 默认选择，无专项权衡；作者开放更换）**

### G4-Q4 「零猜测」的边界 — ⛔ 用户跳过，未获得（不再追问）

### G4-Q6 「消费方是 AI」原则有没有被打破
- **原话**: "是的，AI并不会自己去直接使用，还是依赖人类的决策，人类理解LGDL后，才可以指挥AI去使用"
- **解读**: 🚨 **对定位叙事的重要修正**：作者承认「消费方是 CLI 操作的 AI，不是手写语法的开发者」（design.md:73）存在被打破的现实——AI 不会自主使用 LGDL，仍依赖人类决策；人类需先理解 LGDL 才能指挥 AI 使用。实际消费模型为**双层结构**：
  **人类（理解 LGDL、做决策、指挥）→ AI Agent（执行、经 CLI 操作图）**
  即：AI 是**操作者**，人仍是**决策者与最终消费者**。design.md:73 的绝对化表述应修正为「AI 是直接操作方，但人类必须理解 LGDL 才能有效指挥」。**对全景定位叙事的影响**：LGDL 不仅要对 AI 可操作，还要对人类**可理解**（人要读懂语义才能决策）——与 G3-Q1「开发者直接接触 LGDL 的场景较少」合读，即：人少直接写、但必须读得懂
- **状态**: ✅ 已回填（含定位修正）
