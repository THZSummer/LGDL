### 2.1 单独小节：`group` 是容器节点（统一模型）

> ADR-002 锚点：group 是 `kind:'group'` 的特殊节点，不是独立字段，也不是独立列表。

- **统一模型**：`types.ts:1-9` 模块头 + `types.ts:49-50` 注释（NodeKind 上方：「`group` is a container node that holds other node ids via `contains`」）+ `types.ts:182-187`（LgdlDocument 注释：「The model is UNIFIED: a group is a node with `kind === 'group'` carrying `contains`. There is no separate group list on the document; consumers derive the group container list from `nodes`」）
- **携带字段**：`LgdlNode.contains`（types.ts:143-146 注释「Member ids contained in this group node (node ids and/or other group ids). Only meaningful when `kind === 'group'`; ignored otherwise」）——校验侧「contains 仅限 group」（parser.ts:223-237）
- **投影助手**：`LgdlGroup` 接口（types.ts:169-176）**保留但降级为投影形状**——`deriveGroups(doc)`（groups.ts:24-33）从 nodes 过滤 `kind === 'group'` 投影为 `{id, label, contains, attrs}` 容器形状；`groupNodes(doc)`（groups.ts:15-17）返回完整 group 节点本体。layout/render/status/queries 全部经 deriveGroups 取组（core 文档 §3）
- **布局影响**：layout 把 group 当一等「超节点」参与两层布局（layout 文档 §4），聚合边（任一端是 group id）永不参与节点布局（layout/index.ts:92-98 nodeEdges）

#### ⚠️ 与存量 docs/design.md §5 的差异（漂移标注，仅记录不改）

- **差异定性**：design.md §5「kind 差异显性化」为 **v0.4 时代**文档（当时 group 尚未进入 kind 枚举）；group-as-node（ADR-002）是 v0.6（feature/group-as-node 分支）的语义模型变更——`group` 从旧 `groups:` 顶层字段迁移为 `kind:'group'` 节点（core 文档 §2.3：旧语法已被 parser 拒绝）。**文档未随 v0.6 更新**，属存量漂移（与根级 D2/D6 同源）

## 3. 成员级类型（MemberKind / MemberVisibility）

**成员级类型**（仅 `uml-class` / `er` 图的 `entity` 节点有效——types.ts:138-140 注释「only valid on `kind: entity` nodes in `uml-class` diagrams」）：

| 类型 | 取值 | 源码证据 |
|------|------|---------|
| **MemberKind** | `attribute` \| `method` | types.ts:89（显式枚举——「never guessed from '('」types.ts:103 注释） |
| **MemberVisibility** | `public` \| `private` \| `protected` \| `package` | types.ts:96（显式枚举取代文本内 `+/-/#` 记号约定，注释 types.ts:91-95「the renderer never has to parse markers out of text」） |
| **VIS_SYMBOL** | `public: '+'` `private: '-'` `protected: '#'` `package: '~'` | types.ts:116-121（layout + render 共享的显示符号**单事实源**——layout/index.ts:16 引入、render/index.ts:955 消费） |

**LgdlMember 结构**（types.ts:102-113）：`kind` + `name` 必填；`visibility` / `type` / `params` 可选。约束：attribute 禁 `params`（types.ts:111 注释，校验 parser.ts:190-196）；method `params` 必须 string。

> 交叉引用：core-语义模型.md §3「结构化成员」段落（同口径：可见性用显式枚举，renderer 从不解析 `+/-/#` 标记）。

## 4. 边结构（LgdlEdge）——**无 kind 分类枚举**

**单一事实源**：`types.ts:151-167`。与节点不同，边**没有** kind/分类枚举——只有 5 个结构化字段，全部语义显式：

| 字段 | 类型 | 语义 | 源码证据 |
|------|------|------|---------|
| `from` / `to` | string | 源/目标节点 id——**或 group id（聚合边）** | types.ts:152-155（注释「Source node id — or group id for aggregate edges」） |
| `label` | string? | 关系名，**纯业务语义**——多重性不混入 label | types.ts:156-157（注释「pure business semantics — no cardinality mixed in」） |
| `cardinalityFrom` / `cardinalityTo` | string? | ER/UML 多重性**显性字段**（如 `1`、`*`、`0..1`、`0..*`）——渲染器从不解析 label 中的基数 | types.ts:158-164（注释「Explicit fields — the renderer never parses cardinality out of the label」） |
| `attrs` | LgdlAttrs? | 图专属扩展属性（逃生舱） | types.ts:165-166；`LgdlAttrs = Record<string, unknown>` types.ts:128（未知键由 parser/serializer 原样保留，types.ts:123-127 注释） |

**关键语义要点**：

- **聚合边**：`from`/`to` 为 group id 的边是聚合边——layout 侧被 `nodeEdges` 过滤、永不参与节点布局（layout/index.ts:92-98），由 renderer 在分组框之间绘制（render 文档 §6.3：`routeRectilinear` 绕障 + `shapeEdgePoint('process', box, dir, 8)` 锚定）
- **校验门禁**（core 文档 §2.2 已记录，此处引用不展开）：label 尾部 `1..*` 混入多重性 → error（parser.ts:335-350）；`attrs.cardinality` 逃生舱失效 → error；基数白名单 `1 / * / 0..1 / 0..* / 1..*`（parser.ts:314-331）；边端点必须存在（节点或组）、自环 error、重复键检测（parser.ts:280-313）
- **增量编辑**：有 label 时同 from/to 不同 label 合法（ER 多关系）、无 label 时 a→b 只能一条（mutations.ts:191-200）；removeEdge label 歧义拒绝删除（mutations.ts:229-233）
